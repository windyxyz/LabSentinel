# 任务 07 · 多路并发压测（先读本目录 README.md）

## 背景

架构按多路设计（每路一个 CameraWorker 线程），但只实测过 1 路。M3 目标 ≥4 路稳定。需要压测脚本 + 实测数据回填文档。

## 目标

1. `tools/loadtest.py`：通过 API 注册 N 路文件摄像头（同一演示视频复制多份或同路径多路——注意文件源按原速播放，多路共用同一路径即可代表 N 路解码压力），配好安全区与规则，启动，跑 5 分钟，每 30s 采样：
   - `GET /api/system`（各路 FPS/状态）
   - 进程 CPU%（`psutil`，需 pip 装，用清华源）
   - 事件产生速率（events 表 count 差分）
2. 输出 Markdown 报告表：路数(1/2/4/8) × {各路平均FPS、总CPU%、事件延迟（事件 ts 与视频内进入时刻差，可用录像对照，允许定性）}
3. 结论回填 `docs/40-roadmap.md` M3 段落

## 注意

- LS_ANALYSIS_FPS 默认 5.0/路；压测时对比 5.0 与 2.5 两档
- 直接ML推理是 DirectML 后端（服务端日志可见 backend=directml）
- 若 4 路 CPU 模式就撑不住（某路 FPS<2 或 worker 频繁 error），如实记录，不要美化数据——这是容量规划的依据
- 压测完清掉测试摄像头与数据（脚本带 teardown）

## 验收标准

三种路数跑完、报告落盘 `docs/51-loadtest-report.md`、roadmap 回填、pytest 不受影响。
