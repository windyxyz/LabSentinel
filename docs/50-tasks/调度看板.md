## 巡检规则（自动化任务遵守，每 5 分钟一次，变化驱动）

1. 检测窗口：近 6 分钟文件变化 + 任务文档是否新出现"执行报告"
2. **无变化保持静默**（只记一行）；有变化才行动
3. 小任务完成信号 → 低负载时验收（pytest + npm build）→ 通过晋级/失败生成修复任务
4. 停滞 >45 分钟 → 看板写"⏳ 提示"（同一任务不重复提示）；队列非空且空闲 → 派发队首
5. **训练受控**（2026-10-27 起授权巡检启动）：必须满足《[训练安全规程](./训练安全规程.md)》全部前置条件（CPU<30%×2 采样、flash 10 分钟无变更、无其他重任务、无锁、无摄像头推理），固定限线程命令，训练期间只做文档操作；看门狗每轮检查 `.training.lock`，异常中断不自动重试
6. **禁止**：压测/批量推理、启停用户进程、改 `docs/20-research` 与 `m0-spike`、与用户抢占 8000/5173 端口
7. CPU 负载 >50% 时跳过测试执行，只做文档核对
8. 每次巡检把结论写入"最近巡检"（保留最近 8 条）
9. **额度熔断（10-28 起）**：当前任务文档超过 **45 分钟**无进展（无 `## 执行报告`、mtime 未变）→ 判定 flash 额度暂时耗尽：看板写「⏸ 暂停派发（疑似额度耗尽）」，`派发状态.json` 置 `paused_quota`，**停止派发并删除本定时自动化**；恢复需用户明确指示。
