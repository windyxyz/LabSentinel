# LabSentinel 运维手册（部署单位日常操作一本通）

> 面向：负责让系统**持续跑着**的管理员/值班人员——不需要会开发。
> 安装步骤不在本手册（见 [部署指南](部署指南.md)）；本文从"装完之后"开始。
> 所有命令在**源码根目录**执行；便携包用户把 `python` 换成 `runtime\python.exe`（见 §3）。

## 1. 十分钟上手

1. 安装：解压便携包 → 双击 `安装.bat`（[59 详述](59-portable-install.md)）。
2. 启动：双击桌面 **LabSentinel**（或包目录 `LabSentinel.exe` / `启动.bat`）→ 约 10 秒后浏览器
   自动打开控制面板；首次启动自动播种 4 路演示摄像头。
3. 换成真实摄像头：「摄像头」页 → 添加（RTSP 填地址，USB 直接选设备）→ [§4 排障](#4-摄像头排障)。
4. 画安全区：「安全区配置」页 → 选摄像头 → 多边形圈出要监控的区域。
5. 加规则：「安全区配置」页 → 该摄像头加 `enter`（进入提醒）或 `enter_no_ppe`（未穿实验服告警）。
6. 启动摄像头：摄像头行点「启动」→ 仪表盘应看到 running 与实时事件流。
7. 测告警：「摄像头」页 → 告警面板 →「发送测试」；先在 §5 配好至少一个渠道。
8. 确认闭环：「事件查询」页看到事件 → 处置（确认/误报/忽略）。

## 2. 每日/每周巡检清单

打开**仪表盘**，逐项核对（全部只读，2 分钟）：

| 看什么 | 正常 | 需处理 |
|---|---|---|
| 今日事件 / 未处置 | 未处置不过夜 | 未处置持续累积 → 排值班处置流程 |
| 摄像头状态列 | running + fps 正常 | error（看红字 last_error）/ 画面停滞 / 重连次数上涨 → §4 |
| **磁盘**卡 | 绿色 + 剩余充足 | 变红「磁盘不足，将触发紧急清理」→ 立即 §9 |
| 实时通道 | 已连接 | 断开重连不恢复 → §6 诊断包 |

每周加做（3 分钟）：

- 「摄像头」页 → 告警面板 → 查**投递失败**列表（有失败点「重发」，反复失败 → §5）；
- 跑一次 `python scripts\doctor.py` —— 10 项自检，FAIL 必须处理（[怎么读](部署FAQ.md)）；
- `GET /api/diagnostics/summary` 的 `recent_errors` 有无集中报错（§6）；
- 保留策略预演：`GET /api/maintenance/preview` 看下次清理会删多少（只读不删）。

## 3. 启动 / 停止 / 自启

- **启动**：桌面快捷方式 / `LabSentinel.exe` / `启动.bat`（三选一，行为一致）；
- **停止**：`LabSentinel.exe --stop` 或 `停止.bat`；
- **单实例**：已在运行时再双击只会打开浏览器，不会起第二个服务；
- **端口**：默认 8000，被占自动换 8100–8199 并写进 `config.env`（`port=` 可手工指定）；
  实际端口看启动日志或浏览器地址栏；
- **开机自启**：安装时 `--autostart` 开启；关闭=重装不带该参数，或手动删除注册表
  `HKCU\...\Run\LabSentinel`；被安全软件锁定时改用 `shell:startup` 放快捷方式；
- 服务没起来时页面打不开——先跑 `runtime\python.exe scripts\doctor.py` 自检（§6）。

## 4. 摄像头排障

「摄像头」页状态列会直接给出可读原因（红字=最近错误，自动脱敏不含密码）：

| 现象 | 先查 | 处理 |
|---|---|---|
| error + "打开失败" | RTSP 地址/账号（海康/大华模板见[部署指南 §3](部署指南.md)） | 改地址；USB 换下拉选项；文件确认路径存在 |
| 画面停滞 Ns | 网络抖动 / 摄像头掉线 | 看重连次数是否在涨；自动重连成功会恢复 running |
| 重连次数持续上涨 | 子码流带宽 / 交换机 | 分析建议用**子码流（720p）**；编码用 H.264（H.265 需转码） |
| USB 找不到设备 | 隐私挡板 / 被会议软件占用 | 关 Zoom/腾讯会议；点「刷新设备」；仍不行回退手输索引 |
| 夜间大量误报 | 红外画面分布偏移 | 调 `LS_PPE_CONF`/`LS_PPE_WEARING_CONF`；长期问题走数据飞轮（[手册](标注与模型迭代手册.md)） |

**USB 选择**：添加摄像头选 USB 类型会自动列出本机设备（名称+索引），无需记索引；索引是枚举
顺序仅本机参考，设备名更稳定（拔插/驱动更新后可能变化）。

## 5. 告警排障

- 看渠道配置状态：浏览器开 `http://127.0.0.1:8000/api/alerts/status`（各渠道 configured/投递计数）；
- **一键自测**：「摄像头」页告警面板「发送测试」（未配置的渠道会明确标"未配置"，不产生失败记录）；
- **失败重发**：投递失败列表 → 「重发」；系统本身有 1s/4s/15s 三次退避重试，仍失败进死信；
- 七个厂商渠道申请方式见[部署指南 §4](部署指南.md)；**自建服务**用通用 Webhook（带 HMAC 验签，
  [验签方法](部署FAQ.md)）；
- 邮件渠道高频坑：QQ 邮箱必须用**授权码**（不是登录密码）、端口 465=SSL；
- 全部渠道没反应：先看「实时通道」是否已连接（应用内推送正常=派发器活着），再逐渠道自测。

## 6. 日志与诊断

| 内容 | 位置 |
|---|---|
| 启动器日志 | `logs\launcher-<日期>.log` |
| 服务端日志 | `logs\server.log`（5MB×4 份轮转） |
| 运行中聚合状态 | 浏览器开 `/api/diagnostics/summary`（版本/时长/计数/磁盘/最近 20 条 ERROR） |
| 一键诊断包 | `python scripts\collect_diagnostics.py --out diag.zip --data-dir <data目录>` |

- 诊断包**已脱敏**（令牌/密码/密钥=***，URL 凭证抹除；不含截图/视频/整库）——报障直接发；
- 报障时提供三件套：`/api/system` 的 version、出错请求的 `request_id`（响应头/错误体里都有，
  用 `grep "[req=<id>]" logs\server.log` 定位堆栈）、诊断包；
- 数据库出现 `labsentinel.db-wal`/`-shm` 属正常，**不要手删**（[WAL 说明](部署FAQ.md)）。

## 7. 备份 / 恢复 / 迁移

```bat
:: 备份（运行中可直接备，SQLite 一致快照）
python scripts\backup_data.py backup --data-dir server\data --out backup-20261030.zip
:: 校验
python scripts\backup_data.py verify --zip backup-20261030.zip
:: 恢复到新机（--force 覆盖已有库；不删目标中多出的文件）
python scripts\backup_data.py restore --zip backup-20261030.zip --data-dir <目标data目录> --force
```

- 便携包数据在 `%LOCALAPPDATA%\LabSentinel\data`；换机=新机装同版本 → restore → 启动；
- **只拷 `.db` 文件不行**（会丢 WAL 未合并数据），必须用上面的 backup 命令；
- **配置级迁移**（任务79）：「摄像头」页导出配置 JSON（默认脱敏密码）→ 新机导入（merge/replace）；
  批量部署多路时改 JSON 后导入，免逐路手填；
- 升级前先备份（下一条）；恢复后首次启动自动迁移数据库结构（[迁移说明](部署FAQ.md)）。

## 8. 升级 / 回滚

- **升级**：新版便携包解压 → 再跑一次新包 `安装.bat`（程序覆盖，数据目录不动）→ 完成；
  数据库结构自动迁移；升级后页面若仍旧版：强刷 Ctrl+F5（index.html 已是 no-cache，一般不需要）；
- **回滚**：保留上一版 zip → 停服务 → 旧包重新 `安装.bat` 即可（数据目录不变，数据库向后兼容
  ——但**升级后再回滚**可能遇到新库结构，此时用升级前的备份 restore）；
- **迁移失败**（启动报「数据库迁移 vN 失败」）：停手、保留提示截图、用升级前的备份恢复，然后反馈。

## 9. 容量与性能

- 磁盘预警：仪表盘「磁盘」卡；低于 `LS_DISK_MIN_FREE_GB`（默认 5GB）变红并将自动紧急清理旧事件；
  「按当前增速约 N 天」是**估算值**（近 7 天日均）；
- 保留期：`LS_RETENTION_EVENTS_DAYS`（默认 180 天）/`LS_RETENTION_POOL_DAYS`（90 天）；
- 分析帧率：`LS_ANALYSIS_FPS`（默认 5/路）；多路吞吐实测见 [docs/65](65-multi-rtsp-sim-report.md)
  ——3 路并发 ≈1 核/路（DirectML 串行锁），更多路数待真实摄像头实测；
- 磁盘增长主要来自事件截图/视频：单事件约 8MB 级（含 4 秒视频）；视频存证可在规则层面控制告警量；
- 何时加机器：磁盘卡持续低于阈值且清理后快速回落 / 帧率明显下降 → 降路数或拆分实例。

## 10. 安全与合规

- **管理令牌**：`.env` 设 `LS_ADMIN_TOKEN` 后所有写操作需令牌；可选 `LS_AUTH_READ_PROTECTED=true`
  连读接口也保护；令牌只存浏览器本地；
- **传输**：跨网段/公网访问走反向代理 HTTPS（[部署指南 §1.6](部署指南.md)），不要裸露 8000 到公网；
- **人脸比对默认关闭**：开启前必读[合规章节](部署指南.md)（单独同意+现场标识+留痕），一键清除
  `DELETE /api/face/persons/all`；
- 日志与诊断包的脱敏边界：令牌/密码/密钥/URL 凭证一律 `***`，但**事件文本**（含区域名等）会保留
  ——对外发送诊断包前自行确认可接受。

## 11. 故障速查表

| 症状 | 先查 | 然后 |
|---|---|---|
| 页面打不开 | `runtime\python.exe scripts\doctor.py` | §3 端口/单实例；看 launcher 日志 |
| 摄像头 error / 画面停滞 | 状态列红字 last_error | §4；重连次数在涨=网络问题 |
| 有摄像头但无事件 | 摄像头是否 running、是否画了安全区+加了规则 | 仪表盘实时通道；`camera_soak.py` 采样验证 |
| 告警不发 | `/api/alerts/status` + 一键自测 | §5；失败列表重发；检查退避死信 |
| 磁盘满 | 仪表盘磁盘卡 / `maintenance/status` | §9：调低保留天数 → `maintenance/preview` 预演 → cleanup |
| 升级后页面旧 | 强刷 Ctrl+F5 | [缓存说明](部署FAQ.md)；检查代理缓存 |
| 页面报错带 request_id | `grep "[req=<id>]" server.log` | §6 诊断包报障 |

## 12. 发布后 24h 观察清单（运维视角）

对齐 [摄像头24h验收清单](摄像头24h验收清单.md)，从运维角度关注：

- 每隔 2–4h 扫一遍 §2 巡检项（重点：三路 fps 是否稳定、重连次数、磁盘斜率）；
- `camera_soak.py --all --duration 24h`（任务78）可对**全部路**做 24h 采样，产物 CSV+JSON 汇总
  （含 PASS/WARN/FAIL 判定），接入前先跑 `--preflight` 预检（详见 24h 验收清单 §〇/§二）；
- **回滚阈值**：服务崩溃重启超过 2 次、数据目录增长明显异常（>预估 2 倍）、告警渠道整体失败
  超过 1h —— 先回滚到上一版（§8），再排查；
- 24h 结束：导出证据包（报表页）留档，核对事件数与人工抽查是否一致。
