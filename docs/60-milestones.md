| # | 任务 | 负责 | 验收 | 依赖 |

## M2 · 实时画面 + 人脸比对 + 规则增强（2-3 周）

**目标**：从"能用"到"好用"——看得到实时画面、认得出人、规则更贴实验室管理。

### 2A 实时画面（任务包 01，主力模型/主线）
- go2rtc 网关集成 + Web 端 WebRTC 播放器（组件已拆分可给 flash）
- 验收：局域网端到端延迟 ≤2s；断流自动重连；多路同时观看
- 注意：go2rtc 与分析 worker 共用 RTSP 源，验证摄像头连接数上限（海康默认同源 ≤3 连接——go2rtc 会复制流，正好只占 1 个连接，写进部署文档）

### 2B 人脸比对（任务包 05，主力模型/主线；合规红线见任务书）
- CompreFace 集成（Docker 服务）、注册人员/陌生人事件、同意登记表
- 验收：默认关闭时零行为差异；开启后注册人员进入带名字、陌生人触发事件；CompreFace 故障时降级不阻塞
- **依赖**：真实摄像头稳定运行（M1.5 #4）

### 2C 规则增强（可派 flash，新任务 11 待写）
- 规则维度扩展：白名单时段（如 22:00-06:00 任何人进入告警）、假期模式、摄像头分组
- 事件闭环状态：新事件 → 已确认/误报/忽略（管理者操作），误报数据回流标注池
- 验收：事件表加 status 列 + API + Web 操作按钮；统计页按状态过滤

### 2D 安卓端（任务包 08，主力模型）
- Flutter 骨架（事件列表/详情/设置 + WS 通知）→ 迭代到可用：实时画面（WebRTC flutter 插件）、告警推送（厂商通道后续）
- 验收：apk 安装后连服务器可用；WS 前台通知；后台推送列入 M3

## M3 · 多路 + 通知可靠性 + 报表深化（2-3 周）

**目标**：从单路演示到"整个实验室楼层"的承载力 + 告警必达。

| 任务 | 要点 | 验收 |
|---|---|---|
| 多路压测（任务包 07，修锁后安全） | 1/2/4/8 路 × DML(串行)/CPU 两档；记录 FPS/CPU/内存/事件延迟 | ≥4 路 DML 稳定；回填容量表到部署文档 |
| 推送可靠性 | 安卓厂商通道（小米/华为/OPPO/vivo）或统一推送服务选型；iOS APNs（有开发者账号再说）；告警重试+死信记录 | 手机锁屏收到推送；失败告警可查 |
| 报表深化 | 周/月维度、按规则统计、导出 CSV/PDF（安全汇报用） | 导出文件可直接用于月度安全报告 |
| 规则引擎持久化热更新 | 改规则不重启 worker（当前每次查库，天然支持；补 Web 端即时生效验证） | Web 改冷却期，下一事件立即生效 |
| 数据保留策略 | 事件/截图/视频按天数自动清理（合规：最小化存储） | 配置 N 天后自动删除，含人脸相关数据 |
