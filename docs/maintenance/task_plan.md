# Task Plan — LabSentinel 版本路线图与接力任务

- **`v0.6.x → v0.9.6` 路线图**。见 [docs/plan/v1.0.0-roadmap.md](../plan/v1.0.0-roadmap.md)，包含任务关系、Schema `v22 → v32` 和全部验收门槛。
- **统一 Vulkan GPU 架构草案**：见 [docs/adr/0012-unified-vulkan-gpu.md](../adr/0012-unified-vulkan-gpu.md)（`Proposed`）。
- **`v0.5.0` 历史任务卡与审阅清单**：见 [docs/plan/v0.5.0-ai-dispatch-prompts.md](../plan/v0.5.0-ai-dispatch-prompts.md)。

## v0.6.x → v0.9.6 已确认设计决策（2026-11-23）

- **0.9.6 本地候选验收**。ZIP 与安装器从同一份严格校验的资产组成。Vulkan 保持可选，沿用既有模型、输入尺寸和阈值。性能改动以固定样本识别结果一致为门槛，复用已通过的 AMD 四小时稳定性取证。
- **安装回滚后的卸载**。个人安装实测覆盖升级及回滚后，安装根残留 `labsentinel-server.exe.old`。将此文件纳入卸载清理清单，继续验证默认卸载保留数据。

1. **不做 PDCA 隐患整改工单闭环**：保持产品锐度，合规输出聚焦纯视觉/事件审计、热点热力图、交接备注与防篡改审计证据包 ZIP。
2. **在场、活体与逐人识别（`LS-088`、`LS-091`、`LS-100`）**。空场按低频探测，静止和遮挡保留检测。活体证据用于增强身份可信度，白大褂和口罩独立判定。逐人复核窗口控制请求和耗电，告警仍有事件证据。
3. **Vulkan 为最终默认后端**。按 `LS-086/093` 选型、灰度和跨显卡实测，`LS-095` 在门槛通过后晋升 `auto_vulkan`，永久保留 `DirectML (ls-dml-worker + dml_lock) → CPU` 回退。AMD 四小时同卡结果保留，`LS-100` 用短测复核 Vulkan CV、本机 VLM 和故障回退。
4. **性价比带识图 AI 辅助报告/问答与现成模型整合**：`LS-088` 原生支持 DeepSeek / 通义 Qwen-VL-Flash / 智谱 GLM-4V-Flash 等性价比带识图模型生成持久化安全报告与确定性证据路由多轮问答（首轮 ≤4 张干净原图，后续切 `record_only`）；`LS-080`/`093`/`095` 先盲测现成开源权重（YOLOE 正负对照、`PP-LCNet`、YOLO26、Qwen3-VL/SmolVLM2）并沉淀 7 大训练配方至 `tools/`（2026-11-24 变更：项目定位非商业自用/学习，允许 `SH17`/`FASDD`/`URFD/Le2i` 等 NC/学术数据集用于训练与随包权重，须在 `NOTICE` 如实登记出处与原许可）。

## v0.5.0 已确认设计决策（2026-11-22）

1. **发布节奏**：`LS-050`～`LS-056` 全部纳入 `v0.5.0`，每批全绿提交 `main`，最后由 `LS-057` 统一版本同步、双产物打包与发版就绪。
2. **识别与规则（`LS-050`）**：新增本地「单人留守（`solo_after_hours`）」规则 + 动态映射自定义 PPE 模型类别（`no_gloves`/`no_goggles` 等）+ 网页端可编辑自定义 VLM 提示词模板 + 前端开放 PPE 阈值与灰度诊断（零包体膨胀）。
3. **实时画面与大屏（`LS-051`）**：前端 `<canvas>` 叠加层 + WebSocket 实时检测框/跟踪 ID/合规态（同时兼容 WebRTC 与快照轮播，零重编码开销）+ Rust 进程内托管 `go2rtc`（Windows Job Object 防孤儿）+ 全屏值守大屏与提示音。
4. **运维闭环（`LS-053`）**：告警失败重试后台消费者 + 定时日报/周报自动推送 + 网页端局域网配置（自动生成强随机令牌 + 写 `.env` + 一键优雅自重启）+ Windows `HKCU\...\Run` 开机自启（免管理员、卸载自动清理）。
5. **数据飞轮与便携标注（`LS-054`）**：网页端内置轻量画框标注（AI 预标注打底、缩放平移、数字键切类、SQLite v16 落库）+ 一键导出标准 YOLO 训练集 ZIP（`images/` + `labels/` + `data.yaml`）+ 一键脱敏诊断包 + 复用 `devices` 只读令牌的值守分享链接（24h/7d/30d TTL + 吊销）。
6. **模型架构与训练管道（`LS-055` / `LS-056`）**：`ls-infer` 支持 NMS-free（RT-DETR/YOLO26/YOLOv10）、动态分辨率（640/960/1280）、FP16 与灰度 CLAHE + 网页端模型 A/B 评测；`tools/` 新增多源公开数据集聚合下载（优先 HF 镜像免 Key）、统一词表清洗合并、灰度/远景增强与 `--user-zip` 1:3 混合训练脚本。

## Current Phase

- **`LS-099` 审计包与联动恢复**。离线包携带可验证的事件规则与模型来源设置，并显示截图与记录哈希的核对状态。联动在发送非零级别前持久记录设备，复位确认后再清除。跨重启仍先处理旧设备，防止更换目标时同时激活两台。用隔离 HTTP 设备和服务入口短测取证。
- **`LS-100` 接口登记回归**。按运行程序的 HTTP 方法与路径对照 OpenAPI。补齐集中回归发现的已实现但未登记入口，并让 CI 双向检验。

- **`LS-097` 可选 Retina RTSP 通路**。分析码流弹窗可按机位启用 Retina。受支持的 H.264/H.265 RTSP 视频以原编码和 RTP 时间戳送入现有 FFmpeg 解码及触发片段管线。Retina 失败先用 FFmpeg 重试同一地址，再沿用主码流回退。用回环源验证原编码片段、解码及失败切换。

- **`LS-095` 同卡多路 Vulkan 模型复用**。同资产、同显卡和同精度共享模型，仍对每个入口验证资产。真实 AMD 四路对照确认较低的 GPU 内存占用和约 5 FPS。接续优化首轮与 PPE 尾部时延，并验证 Windows 重启后保持唯一物理显卡选择。
- **`LS-095` 物理显卡选择**。按唯一 Vulkan 设备 UUID 保存可跨重启的选择，使用当前 Windows LUID 对照 ncnn Vulkan 与 DXGI。仍能唯一匹配的旧 LUID 在启动时迁移，无法匹配的选择沿用 DirectML 或 CPU 回退。用更换 LUID 的夹具和 AMD 真机短测验证。
- **`LS-095` PPE 延迟定位**。同帧总耗时保留，各阶段只对实际调用帧统计，并记录样本数。用固定画面区分整图、人物裁剪、白大褂复核及可选口罩模型，再按 CPU、DirectML、Vulkan 对比。
- **`LS-095` PPE 裁剪热路径**。用户确认优先保证识别准确率，性能按实测尽量优化。优先减少原尺寸帧缩放开销，以逐像素等值及固定样本对照为门槛。
- **`LS-100` 上采样复用**。放大人物裁剪时复用相邻输出行的整数水平插值。用 0.9.6 原缩放作逐字节参考，并对照两份发行实例的图片级人数、PPE 计数和违规标记。逐人真值和现场准确率仍按路线图 §6.1 验收。
- **`LS-100` 截图编码记录**。解码后实时流的分析画布为 1280×720，已使用精确双轴 2:1 缩放快路径。现有 JPEG 依赖中的加速可在后续做字节一致与多路对照。
- **`LS-100` 白大褂逐人验收**。现场按白大褂核验，彩色工装与有色实验服的分歧单列，允许后续再训练。Lab Coat Detection 3 v12 的原标签保留作公开参考，另单列视觉复核过的白大褂和普通衣服对照。按人框匹配统计漏检、未知和误报，并用标注人框重跑 PPE 以定位错误阶段。模拟低光只用于同图敏感度测试。
- **`LS-100` 语义搜索验收**。使用隔离数据库建立真实 SQLite 向量索引，对 1 万条 768 维记录测最近邻查询耗时与结果次序。文字编码、检索和权限分别取证。
- **`LS-100` Windows 向量磁盘读取**。默认 WAL 库的万条向量查询超过 30 ms。对照仅在检索期间启用有界映射读取，核对相同排序、并发写入可见性和 Windows 回收数据空间。
- **`LS-101` 本地项目主页**。根据 0.9.6 已有功能和实测状态更新 README。以隔离演示数据从实际候选包截图，GitHub 发布继续等用户本地验收。
- **`LS-101` 本地部署验收**。用当前候选验证全新安装、覆盖安装、归档回滚和默认卸载保留数据。隔离归档使用测试版本标记。历史迁移结果保留作兼容性记录，历代开发阶段安装包不再是当前验收依赖。正常验收发现的问题继续修复。
- **0.9.6 实测范围**。NVIDIA、Intel、现场监控与正式签名等需要外部条件的验证后续进行。本轮保持对应实现、回退、验收入口和已取得的本地证据。模型能力造成的白大褂效果缺口留待更换模型。
- **`LS-101` 发布与签名分离**。手动验收运行可在 GitHub 隔离 Windows 运行器测试个人及全用户安装、服务和全清卸载。正式版本由专用签名运行器签服务程序、重打双产物并签安装器。确认双签名和 SHA-256 后才进入草稿发布。
- **白大褂效果处理**。0.9.6 安装器与 ZIP 继续内置现有人员、实验服和口罩模型，供用户正常检测和测试。记录已知误报和未知样本。用户计划另行训练新模型，拿到权重后用固定样本验证再考虑切换。
- **`LS-100` 裁剪框人员归属**。人物裁剪包含四周边距，原代码直接用区域内的实验服及未穿框，未核对归属。复用整图的唯一归属规则，把裁剪框还原到原图后核对被裁剪的人。用固定素材和相邻人员用例检查风险，再决定是否纳入候选包。
- **`LS-095` Vulkan 冷启动与等待**。已分开统计模型锁等待、拿锁后调用和首次调用。同进程冷缓存仅生成一次，保留资产校验与失败回退。AMD 4/9 路等待短测在门槛内，接续分解原生模型首次加载与推理，优化人员与 PPE 同帧耗时。
- **`LS-095` Vulkan 原生管线复用**。使用固定 ncnn SDK 的 C 接口，以设备为单位在进程内共用编译缓存。跨进程探针对照输出后，将缓存持久化至现有运行时目录，由 Windows 当前账户保护，并验证完整性、驱动兼容和损坏回退。区分设备准备、参数加载、权重及管线创建。
- **`LS-095` 管线缓存清理**。存储管理统计和清理可重建的 Vulkan 管线缓存，沿用原有时限、预览及确认流程。清理只处理符合已知文件名格式的缓存。
- **`LS-095` 白大褂复核 Vulkan 候选**。用随包 ONNX 无损还原转换后的权重，保留原规则及 ONNX 回退。真机已核对小样本最终选框及四路实际调用。接续分解冷启动、排队和推理时延，并按集中验收集核对逐人标签和现场准确率。
- **稳定性验收时长调整（2026-11-25）**。用户确认后续可以缩短。复用已通过的 AMD 四小时证据，取消同类强制多小时重跑。后续按用例完成 4/9 路采样、主动断流恢复、真实问答、事件播放、回退和退出。性能、识别准确度、跨厂商覆盖及权限门槛继续适用。
- **`LS-095` Vulkan 资源协调**。补齐托管本机视觉的设备选择、显存预算、CV 保留量及 CPU 回退诊断。先验证设置、资源不足和启动回退，再随灰度包核对同卡行为。原默认晋升条件按路线图保留。
- **`LS-100` 发行实例组合取证**。组合验证保持真实大屏在线，记录逐路推理、取帧、断流恢复、资源、证据播放、定时本机视觉问答与 Windows 事件。CPU 单路调试短跑已取证，同时修正托管本机模型的 WebP 送图兼容性。后续按 §6 做短时发布构建对照。
- **值守大屏事件补发**。保留授权范围内按编号补发，并在原游标所指记录已过期时提示和刷新事件列表。验证初始事件查询、重连期间的事件和实时推送可以衔接。

- **`LS-098` MCP 独立客户端验收**。隔离发行实例经官方客户端完成协议握手、11 项只读、9 项写操作的拒绝与逐项授权、凭证核验、审计和吊销。视觉复核使用单次受控回环服务。启用语义索引的现场组合回归归入 `LS-100`。

- **灰度遥测复核**。接通 Vulkan 原生调用计数和耗时，核对 PPE 定期采样。另记录实际执行人员与 PPE 的同一帧累计耗时，保留原有规则阶段统计。两者为 `LS-100` 的多路长稳对照提供证据。

### LS-062 · 从管理令牌扩展到访问密码

- **工程边界**。考虑用 Argon2id 保存加盐密码摘要，浏览器使用可撤销、自动过期的 HttpOnly 会话 Cookie。HTTP、WebSocket、媒体与管理端点采用统一权限口径。登录节流独立于告警流量，迁移测试覆盖已有令牌、首次设置、数据备份和密码恢复。 [Argon2 参考](https://www.rfc-editor.org/rfc/rfc9106.html)
- **接入方式**。以实际 TCP 对端和可信 Host 判定本机访问。局域网密码经 HTTPS 反代使用，显式信任本机代理后才接收它覆盖写入的转发协议与客户端地址。管理员 API 令牌继续可用于现有集成。浏览器会话使用随注销或改密关闭的实时画面中继。本机恢复通过服务端命令生成一次性短期恢复码，实际重设在本机网页完成。

### LS-064 · 建立性能、稳定性和识别准确率基线

- 固定提交、构建、Windows 与驱动版本、输入 1080p H.264、分析 5 FPS 和两个随包模型。记录 ORT 版本、CPU 或 DirectML、输入大小、叠加与抓图开关、短期测试与长跑时长。准备纯静止、普通场景、高活动、低光、远景和断流恢复片段，保存对应事件真值。跟踪 1／4／9 路，并区分同时打开大屏的负载。
- 采集分阶段耗时、p50/p95/p99 帧龄与端到端告警延迟、有效分析 FPS、推理和 DirectML 锁等待、采集丢帧、队列水位、恢复时间、内存、CPU/GPU、JPEG 编码和 SQLite 增长。至少覆盖 Windows CPU 与一台 DirectML 真机，现场有条件再覆盖 AMD、Intel、NVIDIA，另测 USB 与多路 RTSP。
- 验收产出同参数可重跑的基准命令和结果表。先确认瓶颈再选择改动，明确拥塞下应牺牲的是画面时效、分析频率或其它可配置项。事故 A1 的进程级 DirectML 串行继续作为硬门禁。

### LS-065 · 多路采集、推理、媒体和页面提速

- **先解决测出的热点**。对 RTSP 采集与预览重复拉流做 A/B，验证可否复用 go2rtc 转发，支持主码流预览与子码流分析。用有界最新帧缓冲和相机公平调度限制延迟，避免积压。证据编码单独限流和观测丢失，触发告警时的证据优先保留。先检查帧拷贝、预处理缓存、空场景 JPEG 持续编码，再选择采集与推理优化。
- **推理与正确性**。在保持进程级 DirectML 串行的前提下，重叠解码和 CPU 预处理。模型格式显式化，修复 RT-DETR 归一化框（审查 05），以真实模型和标注对比输入变换、框与类、CPU／DirectML、FP32／FP16。Motion Gate 与动态帧率保留活动跟踪与周期全检。高事件量时监视证据、告警和 SQLite 写入积压。
- **页面与 API**。摄像头卡仅订阅可见或正在查看的画面，数据到来或尺寸变化时重绘 Canvas。避免隐藏页高频轮询，合并快照请求，评测按相机发布检测元数据的收益。事件列表按需分页或虚拟化。大数据导出纳入内存与 I/O 压测。
- **拟定性能门槛**。同硬件同设置下 4 路场景的 p95 分析帧龄至少下降 20%，或在同延迟及识别质量下增加稳定路数。9 宫格短测检查工作集、断流恢复及进程退出，长期资源趋势按需要单独测量。任何人身安全关键事件的真值用例漏报增加、告警或证据丢失，均需先修正再接受提速结果。实际阈值由 `LS-064` 基线定稿。
- **当前条件**。先进行可由代码路径和分项实验支持的有界采集、媒体更新、模型解码及浏览器负载修正。提速幅度和稳定路数采用同一硬件的全链对照数据验收。

### LS-066 · 人脸模型管理、录入和识别

- **能力现状**。`Face.vue` 和 Rust 路由目前提供 CompreFace 环境变量配置、状态、登记、名单和删除，缺网页端模型管理、本地识别后端及视频识别入口。先做可控的模型测试和人员管理，再接入已授权相机作为事件的身份辅助信息。
- **仿照模型管理的操作路径**。提供关闭、本地和 API 三种模式。可单独配置、启用和停用模型、设为当前、调阈值、查看测试结果、回退到上一模型。相机可继承全局或单独关闭。API 首个适配器复用 CompreFace，配置连通性、超时与配额。本地先评估 ONNX 人脸检测和嵌入组合、CPU／DirectML 支持及可分发许可。切换模型时提示模板兼容性或重新录入，服务不可用时身份标记为未知。
- **录入流程**。参考多角度采集、预览、样本质量提示、录入后试识别和按人管理。为应用内的身份辅助保留同意时间、用途和撤回入口。默认关闭身份识别，模板有明确保留期，原始图片默认仅用于录入处理。远程 API 的相机范围、数据发送、失败重试与删除状态可在网页查看。密码登录由访问控制承担，未知、低置信或未同意时监控和 PPE 继续工作。
- **实现选择**。本地采用 OpenCV Zoo 的 YuNet 与 SFace，权重按版本、许可及哈希独立验证，通过网页按需准备。运行时沿用进程级 ORT 环境与 DirectML 串行锁。CompreFace 模型配置和密钥留在本机，由已有 HTTPS 会话保护。相机主动启用后才为事件做身份辅助，身份结果限管理端查看。
- **验收**。本地、API 分别覆盖录入和撤回、测试图识别、禁用后的热生效、换模型、网络故障、误认与未知人员。测量识别准确率、误接受率、误拒率和延迟，使用经允许的测试素材。用户提供的 EXE 显示 `facewinunlock-tauri 0.4.0`，本机 SHA-256 与官方资产一致，规划参考其公开页面里的录入与测试交互。 [FaceWinUnlock-Tauri 0.4.0](https://github.com/zs1083339604/FaceWinUnlock-Tauri/releases/tag/0.4.0)

### LS-067 · 补齐高频运维工作流与报表

- **实施顺序**。先补事件投递历史与同证据重试、可复用小样本 ZIP 和无人 Cascade 测试，再闭环断流告警、交接、合规与规则演练。

- **运维界面**。首次安装和故障恢复共用清晰的入口，串联接入相机、确认首帧、验证提示和测试告警。值班人员从首页未处置数直达同一筛选口径的事件列表，从「监控状态」直达离线相机与诊断。统一加载、无数据、部分失败和重试的文案与布局。
- **现场接入**。把大华云联和乐橙的内网 RTSP 取流、通道选择、主辅码流及纯云端授权的条件纳入摄像头接入手册。实际兼容性用现场型号与录像机通道验证。
- **第二批**。今日合规指标采用明确的已检查样本或按规则去重的人次作分母，显示未知样本及统计覆盖，样本为零时显示无可用统计（审查 08）。用 Yolo 导出和训练预检处理小样本、缺图及空切分（审查 07）。事件确认误报后可送入现有标注池，经核验后进入训练。添加规则试运行预览，用户能看见触发原因再启用执行。
- **通过条件**。用固定时段和多相机分组样本核对报表、交接和告警计数。提供 USB 断开或模拟 RTSP 掉线的恢复测试、小样本导出与训练预检，并补齐本批公开 API 的响应形状和用户文档。
