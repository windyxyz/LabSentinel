# 架构设计（Rust 单二进制）

> v0.3（2026-11-14 重写，ADR-0011 过渡期结束）：描述**当前唯一实现**——
> `labsentinel-server` 单二进制（控制面 + 分析 worker + 存证 + 告警）。
> 历史口径（v0.2 双运行时 / v0.1 纯 Python）保留在 git 历史与 ADR-0011 中。
> 新增模块前先读本文；变更架构先写 ADR（docs/adr/）。

## 全局视图

```
┌────────────────────── labsentinel-server.exe（axum 单二进制） ──────────────────────┐
│                                                                                    │
│  main.rs / router.rs / middleware.rs——HTTP 路由、Host/CSRF/令牌/限流/审计/安全头     │
│    REST: cameras/zones/rules/events/stats/export/config/alerts/models/plugins …     │
│    WS: /ws/events（事件流）· /ws/webrtc/{id}（go2rtc 信令代理）                      │
│    静态: web/dist（SPA 回退；/assets/* immutable；index no-cache）                  │
│                                                                                    │
│  worker.rs——进程内分析 worker（每路一个线程）                                        │
│    ├─ ls-ingest：ffmpeg 子进程取流（RTSP/文件/USB/folder），analysis_fps 限频          │
│    ├─ ls-infer：ORT（load-dynamic）/ tract，YOLO 前后处理                            │
│    ├─ ls-track：ByteTrack 跨帧关联；ls-analyzer::pipeline：多边形/规则/PPE 级联       │
│    ├─ EventSink：去重 → ls-store 落库 → 快照/存证 MP4 → WS 广播 → 告警派发 → MQTT    │
│    └─ VLM 分支：per-camera analyzer=vlm → vlm.rs（openai_compat/ollama/gemini）      │
│                                                                                    │
│  ls-jobs：retention / 备份 / 升级提醒 / 调度；ls-dispatch：8 渠道 + 重试/死信         │
│  ls-store：SQLite（WAL），schema 自举/向前兼容；fernet.rs：网页渠道密钥加密           │
│  插件：plugins.rs（zip 安装/清单校验/权限/环境白名单/日志）                            │
└────────────────────────────────────────────────────────────────────────────────────┘
        ▲ HTTP/WS（默认 127.0.0.1:8000；局域网需 LS_ADMIN_TOKEN）
┌───────┴──────────────┐
│ Web (Vue3+Vite SPA)   │  仪表盘/摄像头/图片识别/安全区/事件/报表/告警/人脸/模型/设备/设置
│ Android (Flutter 暂缓)│
└──────────────────────┘
```

边界契约：`docs/openapi.json`（HTTP）、`proto/analyzer.proto`（历史 sidecar 契约，
单二进制后仅保留兼容）、`testdata/vectors/*.json`（黄金语料）。

## 分层与模块职责

| 层 | crate/模块 | 职责 | 不做什么 |
|---|---|---|---|
| 入口/中间件 | `ls-server::{main,router,middleware}` | 路由、鉴权（管理/只读/设备三级）、限流、审计、安全头、静态服务 | 不含业务逻辑 |
| 控制面 | `ls-server::handlers::*` | REST 各域（相机/区域/规则/事件/统计/导出/配置/告警/模型/插件/人脸） | 不直接碰推理实现 |
| 分析 worker | `ls-server::worker` + `ls-analyzer` | 取流、节流、推理、跟踪、规则、PPE、存证、事件出站 | 不决定渠道细节 |
| 取流 | `ls-ingest` | ffmpeg 子进程 + 原始帧管道；folder 增量扫描 | 不做推理 |
| 推理 | `ls-infer` | ORT/tract 会话、letterbox、解码/NMS | 不持有业务规则 |
| 跟踪/几何 | `ls-track` / `ls-core` | ByteTrack、多边形、向量契约 | 不发通知 |
| 存储/作业 | `ls-store` / `ls-jobs` | SQLite CRUD/统计/迁移自举；retention/备份/调度 | 不做协议适配 |
| 告警 | `ls-dispatch` | 8 渠道、白名单/https/禁重定向、重试/死信、MQTT 桥 | 不决定"要不要告警" |
| 模型接入 | `ls-server::vlm` + 模型管理 | 本地 ONNX / 自备 ONNX / 外部 VLM 三选一（按摄像头插拔） | 不训练模型 |

## 线程/进程模型

- **tokio 运行时**：HTTP/WS 异步；阻塞型工作（推理、ffmpeg、DB 写）走 `spawn_blocking`
  或专用线程，避免阻塞事件循环。
- **worker ×N**：每路一个线程，持独立检测器/跟踪器；重启退避 1/5/30/60s，存活 >5s 重置，
  超过上限转 `error`（手动启动重新纳入守护）。
- **告警派发**：`EventSink` 投递到后台线程（同步 HTTP 渠道不阻塞帧循环）；MQTT 由
  `ls-dispatch` 的独立客户端发布。
- **folder worker**：轮询目录（含子目录）→ 4 元组（camera,path,mtime,size）去重 →
  本地检测或 VLM 判定 → 回填 `folder_images` + 违规事件。
- **静态服务**：`tower-http` ServeDir + SPA 回退；`/assets/*` immutable 一年，
  `index.html`/路由回退 no-cache。

## 推理路径与模型策略

1. 本地模型：`LS_MODEL_PATH`（基础检测）/`LS_PPE_MODEL`（实验服）或网页「模型管理」选择；
   `ORT_DYLIB_PATH` 指向 onnxruntime 动态库（发行包已带）。
2. 外部联网模型：`settings model.active` 或 `LS_VLM_*`；`vlm.rs` 三 provider——
   openai_compat（通用多帧 ≤8）、ollama（本地）、gemini（原生视频 inline_data）。
   per-camera `PUT /api/cameras/{id}/analyzer {"analyzer":"vlm"}` 插拔；失败降级落
   error 不误报。视频 worker 按路限流抽帧（默认 6 次/分钟）。
3. 后端：CPU 默认（ort/tract）；GPU(DML) 变体随发行包/构建选项提供。推理入口统一封装在
   `ls-infer`，业务代码不直接调用 `sess.run`。
4. 黄金语料分层容差（同后端逐位、跨后端 IoU/事件一致率）见 ADR-0009。

## 事件模型（术语见 GLOSSARY）

```
进入安全区事件流：
  track 进入 zone → ZoneState.entered=True
    → PPE 判定（三级证据）：no(显式 No Lab Coat) / wearing(Lab Coat≥阈值) / unknown
    → 规则匹配（enter / enter_no_ppe / exit / occupancy_over）
    → ls-store 落库（快照/视频存证）→ WS 广播 → ls-dispatch 外部渠道
```

**设计原则**：证据不足判 unknown 不判违规（防误报伤信任）；冷却按 (rule, track)；
occupancy_over 用 track=0；规则条件顺序：星期 → 假期 → 时间窗 → 冷却。

## 部署拓扑

- **Windows**：Rust 单包 zip（模型/ffmpeg/onnxruntime/前端/`LabSentinel.bat`），解压即用；
  升级 `--archive`、回滚 `--rollback`（ADR-0011 执行结果）。
- **Linux**：Rust 单二进制 + systemd（`deploy/systemd/labsentinel.service`）；Docker 已终止。
- 数据目录：默认 `data/`（`LS_DATA_DIR`）；发布包启动器默认 `%LOCALAPPDATA%\LabSentinel\data`。
- 模型不随源码入库：哈希锁定于 `scripts/assets.lock.json`，
  `scripts/prepare_rust_assets.py` 准备资产。

## 架构约束（写代码前必读）

1. 推理只走 `ls-infer` 封装；业务代码出现裸 `sess.run` 即拒。
2. 新增 API 走 `ls-server/src/handlers/`，契约同步 `docs/openapi.json` 与
   `docs/dev/api-reference.md`；路由清单由 `--dump-routes` 供覆盖率脚本统计。
3. SQL 一律字面量 + 参数占位符（禁止拼接）。
4. 外部 URL 必须域名白名单（防 SSRF）；回环服务请求禁用系统代理。
5. 每路 worker 内不得有 >100ms 阻塞操作（除推理排队）；慢操作入队/线程池。
6. 前端不引入重型图表/UI 库（bundle 预算 gzip ≤100KB）。
7. 非回环监听必须配 `LS_ADMIN_TOKEN`，否则拒绝启动；WS 校验 Origin 与令牌。
