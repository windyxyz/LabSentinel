# 杀毒软件误报说明

> 适用对象：Windows Defender / 卡巴斯基 / 360 等对 LabSentinel 发行包报
> 「HEUR:Trojan…」类启发式告警的用户与维护者。
> 本文档解释：为什么会被启发式命中、我们已经做了什么、用户需要做什么。

## 为什么会被误报

LabSentinel 的合法工作形态与恶意软件的技术画像有部分重叠：

| 特征 | 恶意软件常见用途 | LabSentinel 的实际用途 |
|---|---|---|
| 未签名 EXE 常驻并监听本地端口 | 后门 / C2 | `labsentinel-server.exe` 提供本机 Web 控制台（默认仅 127.0.0.1） |
| 拉起第三方二进制（ffmpeg.exe / go2rtc.exe） | 进程注入跳板 | RTSP/视频取流与 WebRTC 实时画面网关（来源与许可见 NOTICE） |
| 写用户目录数据 | 持久化 | `%LOCALAPPDATA%\LabSentinel\data` 的事件库/截图/视频（数据不出本机） |
| 无签名 / 无版本信息的 EXE | 打包器产物 | 证书未到位前的预览版（0.3.0 起为 Rust 单二进制） |

启发式引擎不看用途只看行为组合；**这不是检测到恶意代码，代码全部开源、可审计**
（AGPL-3.0）。Rust 运行时不解释执行脚本、无 `eval/exec`、无动态下载代码。

## 我们已经做的

1. **单一静态二进制**：控制面 + 分析 worker 编进 `labsentinel-server.exe`，
   不再有「解释器 + 脚本」启动链；
2. **外部二进制来源固定**：ffmpeg/ffprobe、go2rtc、onnxruntime 由
   `scripts/prepare_rust_assets.py` 按 `scripts/assets.lock.json` 的 SHA256 校验获取；
3. **无提权**：默认按当前用户运行，不请求 UAC；服务模式需管理员显式安装；
4. **数据边界清晰**：仅写 `%LOCALAPPDATA%\LabSentinel`（或 `LS_DATA_DIR`），
   不写系统目录/注册表 Run 键（开机自启由用户放置快捷方式）。

## 用户需要做的（证书到位前的过渡措施）

误报无法 100% 避免（代码签名是根治手段）。遇到告警时：

1. **确认来源**：只从本项目 GitHub Release（或维护者分发渠道）获取 zip；
   用 `SHA256SUMS-rust.txt` 校验下载文件。
2. **加入排除/信任区**（二选一，推荐同时排除解包目录与数据目录）：
   - 解包目录（含 `tools\`）
   - `%LOCALAPPDATA%\LabSentinel\`
   - 卡巴斯基：设置 → 威胁与排除项 → 管理排除项 → 添加上述目录；
   - Windows Defender：Windows 安全中心 → 病毒和威胁防护 → 管理设置 → 排除项。
3. **提交误报**（帮助所有人）：
   - 卡巴斯基 Open False Positive 通道：opentip.kaspersky.com
   - Microsoft：microsoft.com/wdsi/filesubmission（选 Software developer）
4. **不要**使用来路不明的"破解版/绿色版"——那才是真风险。

## 维护者事项（根治路径）

- [ ] 代码签名证书（Certum/SSL.com）申请后接入 `release.yml` sign 步骤——签名后
      启发式误报基本消失；
- [ ] 若仍命中：以具体 SHA256 提交 opentip 误报申诉，通常 1-3 个工作日白名单化；
- [ ] 每次发布前用 Windows Defender 命令行抽查一次：
      `"%ProgramFiles%\Windows Defender\MpCmdRun.exe" -Scan -ScanType 3 -File <解包目录>`
