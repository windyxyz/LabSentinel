# 68 · 图片文件夹自动识别（使用手册）

> 适用场景：实验室内的另一套软件会把画面/结果**持续截图**写入一个目录（本地盘、移动盘或
> 网络共享均可）。LabSentinel 自动读取新图片，识别人员与实验服，按安全区规则汇报关键图片、
> 对显式违规产生事件与告警。**原有的 RTSP / 视频文件 / USB 摄像头接入完全保留。**

## 1. 五分钟上手

1. 打开「摄像头」页，类型选 **图片文件夹**，名称随意，路径填截图目录（如
   `D:\screenshots` 或 `\\nas\share\lab-shots`），勾选“立即启动”，点添加。
   - 目录必须已存在；支持中文路径与子目录（默认递归）。
   - 不勾“立即启动”可以先画安全区、加规则，再回来启动。
2. 到「安全区配置」页选择该文件夹源，点“看快照”拉取最近一张识别画面，在 1280×720 画布上
   画安全区（与视频源同一套坐标）。
3. 到「安全区配置」页添加规则：
   - `enter_no_ppe`（进入安全区未穿实验服）：**图片源默认唯一会触发告警的规则**；
   - `occupancy_over`（人数超限）：图片内在区人数超过阈值时触发；
   - `enter`：默认不触发（图片没有“进入”这一时刻），需要时设 `LS_FOLDER_ENTER_EVENTS=true`。
4. 打开「图片识别」页：
   - **关键图片（有人）**：筛选出所有检测到人员的图；
   - **仅违规**：只看有显式违规证据的图；
   - 点图片看原图、识别详情、关联事件；筛选文件夹/时间范围，汇总卡显示数量。

## 2. “关键图片 / 违规”的判定

| 标记 | 条件 | 用途 |
|---|---|---|
| 有人（`persons>0`） | 人体模型检出至少 1 人 | 关键图片汇报（默认筛选） |
| 在区（`in_zone`） | 人员锚点（框底边中点）落在任一安全区内 | 区域统计 |
| 关键（`key=1`） | 有人 | 需要人工关注的候选帧 |
| 违规（`violation=1`） | 在区人员的实验服判定为 `no`（显式 `No Lab Coat` 证据，≥ `LS_PPE_CONF`）；或人数超限 | 事件/告警/重点复核 |

**“实验服状态不确定”不算违规**：模型未配置、置信度不足或域外画面时只记 `unknown`，
不会把“证据不足”当“未穿”，避免对合规人员误报。

图片之间没有时间连续性，因此：
- 不产生 `exit` 事件；
- 默认不为每张截图产生 `enter` 事件（否则每张图都像“新进入”，告警语义错误）；
- 同一条规则的告警按冷却期限频，但**每张图仍会入库**，汇报不丢图。

## 3. 目录与文件要求

| 项 | 默认/说明 |
|---|---|
| 格式 | `.jpg .jpeg .png .bmp .webp .tif .tiff`（`LS_FOLDER_EXTS`） |
| 子目录 | 递归（`LS_FOLDER_RECURSIVE=true`；点开头的隐藏目录跳过） |
| 文件大小 | ≤ 32MB（`LS_FOLDER_MAX_FILE_MB`），空文件/超大文件跳过 |
| 写入中文件 | 修改时间静置 ≥1.5s 才读取（`LS_FOLDER_STABLE_S`），避免半张图 |
| 轮询 | 3s（`LS_FOLDER_POLL_S`）；「立即扫描」可马上触发一轮 |
| 单轮限量 | 20 张（`LS_FOLDER_MAX_PER_TICK`），剩余下一轮继续，状态里显示“待处理” |
| 识别速度 | 每路最多约 5 张/秒（`LS_ANALYSIS_FPS`），与视频共用 DML 串行锁 |
| 增量 | 目录 mtime 未变不重复枚举；每 5 分钟全量补扫一次（`LS_FOLDER_FULL_RESCAN_S`） |
| 规模 | 单次枚举上限 **5 万张**（新图优先；超出会在摄像头状态提示归档/按日期分子目录） |
| 去重 | 路径+大小+修改时间；服务重启/重扫不会重复识别 |

**原始截图只读**：系统不移动、不改名、不删除源文件。违规图片会另存一份证据副本到
`data/snapshots/`，保留 30 天后自动清理（`LS_RETENTION_IMAGES_DAYS`）；列表缩略图缓存在
`data/thumbs/`。删除该摄像头时，识别记录/证据/缩略图一并清理，源目录不动。

## 4. 汇报与事件

- 「图片识别」页汇总卡：接入文件夹数、近 N 天识别总数、关键图片数、违规图片数、读取失败数、
  当前文件夹待处理数；支持按文件夹、24 小时/7 天/30 天/不限、关键/仅违规/全部筛选；
  右上角「导出 CSV」按当前筛选导出（UTF-8 BOM，Excel 直接打开，最多 5 万行）。
- 违规图详情里显示关联事件 ID；到「事件查询」页可处置（确认/误报/忽略）并按既有渠道告警。
  同一张图命中多个区域时可能关联多个事件，图片行记录第一个事件 ID。
- 原始截图被外部软件轮转删除后，违规图仍可从证据副本查看（其它图显示 404 占位）。
- 读取失败（损坏/非图片）会以 `error` 记录出现在列表（选“全部已识别”可见），不会反复重试。

## 5. 常见问题

**Q：状态显示 `error`，提示“文件夹不存在或不可访问”？**
目录被移动/改名、移动盘未插、网络共享断线。服务会每 5–6 秒重试，目录恢复后自动转为
`running`；也可以删除后重新添加（路径已变时）。

**Q：识别数一直为 0 / 待处理很大？**
先看「摄像头」页的“最近”文件名与错误；确认目录里确实有新图、文件格式在扩展名白名单、
文件已静置 1.5s。若目录极深/极大，可调大 `LS_FOLDER_MAX_PER_TICK` 或缩短轮询间隔
（注意不要和视频源抢推理）。

**Q：有关键图片但没有违规/告警？**
① 未配置实验服模型（`LS_PPE_MODEL`）时只能判 `unknown`；② 未添加 `enter_no_ppe` 规则；
③ 现场画面与模型域差异导致 `No Lab Coat` 置信度不足（看「模型状态」与 历史模型评估记录）；
④ 规则处于冷却期——图片仍会入库，只是不重复告警。

**Q：同一张图被识别两次？**
去重依赖路径+大小+修改时间。截图软件若重写同名文件且大小/mtime 完全不变，会被视为同一文件；
可让其生成唯一文件名（推荐），或等待 5 分钟全量补扫后按新 mtime 识别。

**Q：网络盘很慢/大量历史文件？**
首次启动会按 mtime **从新到旧**限量处理（新图优先保证告警时效），状态里能看到“待处理”；可先把历史图片移走，
或临时调小 `LS_FOLDER_MAX_PER_TICK` 降低对网络盘和推理的占用。历史文件识别后不会再重复。

**Q：图片被旋转/拉伸，区域对不上？**
识别画布统一为 1280×720（与视频源一致），原图按比例拉伸到该画布后判定；安全区请在该画布上画。
手机竖屏截图会明显拉伸，建议让截图软件输出 16:9 画面。

**Q：能否直接分析 PDF/Word 截图？**
当前只读取图片文件；需要先由外部软件把内容导出为图片（这正是本功能的接入方式）。

**Q：会不会和视频摄像头抢 GPU？**
所有 DML/VitisAI 推理共用全局串行锁，图片源逐张、限速处理；但仍建议不要同时跑多路视频+大量
图片积压。重负载（训练/压测/24h）时先停图片源。

## 6. 配置速查（环境变量，全部可省略；网页端无需配置）

```ini
LS_FOLDER_POLL_S=3
LS_FOLDER_STABLE_S=1.5
LS_FOLDER_MAX_PER_TICK=20
LS_FOLDER_RECURSIVE=true
LS_FOLDER_EXTS=.jpg,.jpeg,.png,.bmp,.webp,.tif,.tiff
LS_FOLDER_MAX_FILE_MB=32
LS_FOLDER_FULL_RESCAN_S=300
LS_FOLDER_ENTER_EVENTS=false
LS_RETENTION_IMAGES_DAYS=30
```

改完重启服务生效（`LS_` 前缀，pydantic-settings 读取）。

## 7. API 速查

```bash
# 汇总（近 7 天，按摄像头）
GET /api/folder-images/summary?days=7

# 关键图片（有人）列表；violation=1 只看违规
GET /api/folder-images?camera_id=1&key=1&limit=60
GET /api/folder-images?camera_id=1&violation=1&start_ts=2026-11-01T00:00:00

# 单张详情 / 原图 / 缩略图
GET /api/folder-images/123
GET /api/folder-images/123/file
GET /api/folder-images/123/thumb

# 按当前筛选导出 CSV（Excel 直接打开；≤5 万行）
GET /api/folder-images/export.csv?camera_id=1&violation=1

# 立即扫描（运行中唤醒；未运行则启动）
POST /api/folders/1/scan
```

开启读保护（`LS_AUTH_READ_PROTECTED=true`）时，媒体 URL 需带 `?token=`（前端已自动处理）。
