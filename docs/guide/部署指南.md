# LabSentinel 部署指南

> 面向对象：会装 Python、但第一次接触本项目的实验室管理员/运维。
> 照着做完即可获得：Web 端看实时画面与事件、按需配置告警渠道、按需开启人脸模块。
> 配置项完整清单见 [server/.env.example](../server/.env.example)。

## 0. 部署形态选择

| 形态 | 适用 | 优点 | 限制 |
|---|---|---|---|
| **安装包（推荐入门）** | Windows 单机、想要标准软件体验 | 双击 `LabSentinel-setup-<ver>.exe` 安装→开始菜单/控制面板卸载项；升级自动覆盖；Inno Setup 6 编译（ADR-0010） | 需随包 ISCC 编译；未签名预览版 SmartScreen 会提示 |
| **便携包 zip** | 免安装、放 U 盘/临时试用 | 解压双击 `LabSentinel.exe` 即用，自带嵌入式 Python，数据与卸载可控 | 体积大（安装后 ~716MB）；无安装向导 |
| Windows 原生 | 单机、本机有摄像头/视频文件、要用 DirectML/NPU 加速、需要改代码 | 可用核显加速，部署最简单 | 需要自己装 Python |
| Docker（Linux） | 已终止 | — | Docker 支持 2026-11-11 终止（产物已移除）；Linux 请走 systemd 原生部署（部署指南-Linux.md） |

本仓库当前发布**双形态**：同一 `Resources/dist/portable/LabSentinel/` staging 由
`scripts/build_portable.py --zip --installer` 同时产出 zip 与 setup.exe（mpv.net 先例）。
**便携包的安装/升级/卸载/数据位置/自启**：见 [59-portable-install.md](安装与卸载.md)；
安装包策略与选型见 [ADR-0010](adr/0010-installer-strategy.md)；打包方法见构建脚本
scripts/build_portable.py。

> **单端口模式（生产/打包推荐，任务43）**：`cd web && npm run build` 之后**只开 8000** 即可——
> 服务端自动托管 `web/dist`（可用 `LS_WEB_DIST` 指向其他目录），浏览器直接访问
> `http://127.0.0.1:8000`，前端路由刷新（如 /events）不 404；无需 Vite/Node 常驻。
> 开发时仍可另开 `npm run dev`（5173 热更新），互不影响。
> **缓存策略（任务72）**：`/assets/*`（内容 hash）缓存一年 immutable；`index.html`/路由回退
> no-cache（升级即生效）；其余静态 1h；文本类响应 ≥1KB 自动 gzip（视频/zip/截图不压，Range 优先）。

## 1. Windows 原生部署

### 1.1 前置

- Windows 10/11 x64；Python **3.11+**（本仓库开发环境为 3.14）
- 磁盘：代码 + 模型约 1GB；事件截图/视频另计（每事件约 8MB 视频，见容量规划）
- 端口：8000（API，S1 起默认仅本机可写）、5173（Web 开发服，生产可换 nginx 托管 dist）、127.0.0.1:1984（go2rtc 控制面，**仅回环+Basic 鉴权**，T-101）、8555（go2rtc WebRTC 媒体面 UDP/TCP；RTSP 再分发已关闭）

### 1.2 获取代码与模型

```bash
git clone <本仓库>
cd 监控识别
```

模型文件不随仓库分发，二选一：
- **直接下载**：yolo11n.onnx（人员检测，COCO 预训练）放置 `m0-spike/`
- **自己训练/导出**：按 [tools/README.md](../tools/README.md) 执行 `download_datasets.py → train_ppe.py → export_onnx.py`
  （实验服模型 `m0-spike/yolo11n_ppe.onnx`；类目顺序见任务 06 执行报告）

### 1.3 创建 venv 并装依赖

首选 `scripts\deploy.py`（自动建项目内 `.venv`、装依赖、下载 OpenH264/node/ffmpeg、写
`scripts\venv_path.txt`，`一键启动.bat` 也会自动调用它补环境）：

```bat
python scripts\deploy.py install
```

手动等价：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r server\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> 铁律：`supervision==0.25.1` 不可升级（0.26+ 移除 ByteTrack）；`onnxruntime` 与
> `onnxruntime-directml` 不可同装（Windows 用 directml 版；CPU 版仅用于 CI/兼容）。
> 训练/量化另用专用环境（见 [tools/README.md](../tools/README.md) 的 m0-venv/npu-venv），
> 与服务端 `.venv` 互不相干。

### 1.4 配置

复制 `server/.env.example` 为 `server/.env`，按需修改（可全部留空先跑起来）。

### 1.5 一键启动

```bat
scripts\start-all.bat
```

会开三个窗口：go2rtc（1984）→ uvicorn（8000）→ vite dev（5173）。
浏览器打开 http://localhost:5173：
添加摄像头（RTSP 地址或视频文件路径）→ 画安全区 → 加规则（enter/enter_no_ppe/exit/occupancy_over）→ 启动 → 看事件与实时画面。

只用后端 API 时（单端口构建后连 UI 一起跑更简单，见 §0 形态表）：
`cd server && ..\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000`

### 1.6 生产化（可选）

- Web：`cd web && npm run build`，把 `dist/` 交给 nginx/IIS，`/api` 反代到 8000
- 开机自启：任务计划程序或 NSSM 注册三个进程；go2rtc 必须带 `--config tools\go2rtc.yaml`
- 防火墙放行 8000/TCP、8555/UDP（WebRTC 媒体；go2rtc 控制面 1984 只绑回环，**不要**对外放行——T-101）
- 浏览器与 go2rtc 需网络互通；跨网段/公网访问请走 `wss://` 反向代理

### 反向代理/HTTPS 与安全头（任务89）

服务端自带基础安全响应头（`LS_SECURITY_HEADERS=1` 默认开）：nosniff/DENY/no-referrer/
Permissions-Policy/CORP: same-site。CSP 默认不发送——首次启用建议先 Report-Only：

```env
# LS_CSP=default-src 'self'; connect-src 'self' ws: wss: http://127.0.0.1:*
# LS_CSP_REPORT_ONLY=1
```

Nginx 最小反代示例（HSTS 由代理层加）：
```nginx
server {
    listen 443 ssl;
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
    }
    add_header Strict-Transport-Security "max-age=31536000" always;
}
```

### 1.7 常见问题（Windows）

| 现象 | 原因/处理 |
|---|---|
| 视频有画面但浏览器播不了事件视频 | 缺 OpenH264 编码库：把 `openh264-2.5.0-win64.dll` 放到服务端 venv 的 `Lib\site-packages\cv2\`（项目 `.venv`；server/app/__init__.py 已自动加 PATH）；仍失败会回退 mp4v（ffplay 可播） |
| 实时画面一直"重连中" | go2rtc 未启动 / 1984 被防火墙拦 / 用 IP 而非 localhost 时 mDNS 候选失败 |
| 2 路以上分析后摄像头"静默停止" | 旧版本 DirectML 并发 bug，已在 engine.py 全局串行锁修复（2026-10-26）；确认服务端已重启到新代码 |
| pip 安装超时 | 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`；npm 加 `--registry=https://registry.npmmirror.com` |

## 3. 摄像头接入

> **现场实施一条龙**（预检→接线→区域→告警→24h）见 [摄像头接入Runbook](摄像头接入Runbook.md)。

### 3.1 发现助手（任务113）

不知道摄像头 IP/RTSP 路径时：「摄像头」页 → 添加表单下方**发现摄像头（局域网）** →
搜索（WS-Discovery/ONVIF，UDP 3702 组播）→ 对结果"探测"确认 RTSP 口与编码 →
选品牌模板**填入表单**，把占位的 `用户名:密码` 改成真实账号（建议子码流 102/subtype=1）。
搜不到的常见原因：跨网段、摄像头未开 ONVIF、防火墙拦组播、AP 隔离——此时手输模板即可。
助手只读探测，不会自动添加或启动摄像头。

| 品牌/来源 | RTSP 地址模板 | 说明 |
|---|---|---|
| 海康威视 | `rtsp://用户名:密码@IP:554/Streaming/Channels/101`（主码流）/ `102`（子码流） | 分析建议用子码流（720p） |
| 大华 | `rtsp://用户名:密码@IP:554/cam/realmonitor?channel=1&subtype=0`（主）/ `subtype=1`（子） | |
| 宇视 | `rtsp://用户名:密码@IP:554/media/video1` | |
| 手机模拟 | 手机装"IP 摄像头"类 App，取局域网 RTSP 地址 | 联调用；务必用 5GHz 局域网 |
| 视频文件 | 直接填文件路径，类型选"视频文件" | 演示用；`LS_FILE_LOOP=true` 可循环 |

注意事项：
- 摄像头编码建议 **H.264**（浏览器 WebRTC 直通）；HEVC 需 go2rtc 转码（`ffmpeg:` 源加 `#video=h264`）
- 分析帧率默认 5 FPS/路，`LS_ANALYSIS_FPS` 可降；多路并发能力见历史压测记录
- 摄像头账号建议用只读/子码流专用账号

### 3.1 USB 摄像头 / OBS 虚拟摄像头（联调）

没有真实 IP 摄像头时，可用本机 USB 摄像头或 OBS 虚拟摄像头验证设备链路。
**"添加摄像头"页面选 USB 类型会自动列出本机设备（名称+索引），直接下拉选择即可，无需记索引**；
点「刷新设备」可重枚举（接口异常时回退手动输入索引）。

```bat
:: 1. 枚举可打开的索引（并保存首帧确认画面）
python tools\list_cameras.py --snapshot-dir logs\cam_probe

:: 2. 用 OBS Virtual Camera 播放演示视频（需已安装 OBS 虚拟摄像头驱动 + pyvirtualcam）
python tools\virtual_cam_feed.py --video m0-spike\data\lab-walk-24076.mp4
```

然后在「摄像头」页添加：类型 **USB**、设备号填 `0`（物理摄像头）或 `1`（OBS 虚拟摄像头，以枚举结果为准）。
服务端会把 `"0"`/`"1"` 转成 OpenCV 设备号；USB 常返回 `fps=-1`，服务端已按 30 兜底。

注意：
- OBS 虚拟摄像头只用于联调，**不能替代真实 RTSP 24h 验收**；
- 物理摄像头黑屏先检查系统隐私开关/物理遮挡；
- `virtual_cam_feed.py` 依赖 `pyvirtualcam`（`pip install pyvirtualcam`），不要与真实摄像头验收同时跑。

## 3.5 管理鉴权（可选，任务16）

首启/升级会**自动生成管理令牌**（Q-02/T-104：写入 config.env，仅显示一次——见数据目录 FIRST_RUN_TOKEN.txt，保存后删除）。绑定非回环地址（LS_HOST）且无令牌会拒绝启动。手动轮换：

```ini
LS_ADMIN_TOKEN=your-secret-token    # server/.env；为空即不启用
```

- 启用后**所有写操作**（POST/DELETE：加删摄像头/安全区/规则、事件处置、死信重发、维护清理、人脸注册删除）
  需带请求头 `X-Admin-Token: <token>`，否则 401
- `GET /api/system` 永不拦截（健康检查）；读操作默认放行，`LS_AUTH_READ_PROTECTED=true` 可一并保护
- Web 端：在「摄像头」页顶部填写令牌（仅存浏览器 localStorage），401 时会有明确提示
- WS 实时推送：令牌经 Sec-WebSocket-Protocol 子协议传递（T-106，不进 URL/日志）；读保护开启时 WS 与 HTTP 同口径
- WebSocket：`ws://host/ws/events?token=<token>`（URL 传参有日志泄漏风险，建议内网用）
- 部署验收：`POST /api/alert-test` 会逐渠道自检（含 401 路径验证）

## 4. 告警渠道配置

**推荐：网页端「告警配置」页**（管理员）——按渠道卡片填写 Webhook/Key/邮箱授权码，点「保存」
立即生效，无需改 `.env` 或重启；支持单渠道「发送测试」。密钥只保存在本机数据库且不回显，
留空保存=保持原值，「清除」=回退启动时 `.env`。下表保留 `.env` 变量口径，供高级/批量部署使用。

| 渠道 | 去哪拿 | 配置项 | 备注 |
|---|---|---|---|
| 应用内 | 无需配置 | — | Web 端右上角 WS 状态，事件实时弹出 |
| 企业微信 | 群 → 添加群机器人 → 复制 Webhook | `LS_WECOM_WEBHOOK` | 仅 `qyapi.weixin.qq.com` |
| 钉钉 | 群设置 → 智能群助手 → 添加机器人 → 自定义 | `LS_DINGTALK_WEBHOOK` | 仅 `oapi.dingtalk.com` |
| 飞书 | 群设置 → 群机器人 → 自定义机器人 | `LS_FEISHU_WEBHOOK` | 仅 `open.feishu.cn` |
| 微信（Server酱） | sct.ftqq.com 微信扫码登录 → SendKey | `LS_SERVERCHAN_SENDKEY` | 推送到微信服务号 |
| 微信（PushPlus） | pushplus.plus 微信登录 → token | `LS_PUSHPLUS_TOKEN` | 公众号消息 |
| QQ（Qmsg酱） | qmsg.zendee.cn 登录 → key | `LS_QMSG_KEY` + `LS_QMSG_QQ` | 需加机器人好友；QQ 侧风控严 |
| 邮箱 | QQ 邮箱：设置 → 账户 → 开启 SMTP → 授权码 | `LS_SMTP_HOST/PORT/USER/PASS` + `LS_ALERT_EMAIL_TO` | 端口 465 走 SSL |

| 通用 Webhook | 自建服务（n8n/自研平台/局域网网关） | `LS_WEBHOOK_URL`（+`LS_WEBHOOK_SECRET`/`LS_WEBHOOK_ALLOW_HTTP`/`LS_WEBHOOK_TIMEOUT_S`） | HMAC 签名，见下 |

**通用 Webhook（任务67）**：POST JSON `{"version":1,"title":"LabSentinel 级别N告警","text":"…","level":N,
"ts":"…","source":"labsentinel","event_id":..,"camera_id":..,"type":"..","detail":".."}`；
配置 `LS_WEBHOOK_SECRET` 后每个请求带 `X-LS-Signature: sha256=<hex hmac_sha256(secret, 原始body)>`、
`X-LS-Event: alert`、`X-LS-Timestamp`。默认仅允许 https；自建 http 服务设 `LS_WEBHOOK_ALLOW_HTTP=true`。
接收方验签（原始 body 字节，不要先 json 再重序列化）：

```python
import hmac, hashlib
ok = hmac.compare_digest(
    hmac.new(SECRET.encode(), raw_body, hashlib.sha256).hexdigest(),
    request.headers["X-LS-Signature"].removeprefix("sha256="))
```

**按渠道过滤（任务86）**：`LS_ALERT_FILTERS`（JSON）可让指定渠道只收特定级别/类型，例如
`{"email":{"min_level":3},"wecom":{"types":["enter_no_ppe"]}}`——email 只收 L3+，
企微只收未穿实验服。被过滤的事件不建投递行（与"未配置"语义一致）；`alert-test` 不受过滤影响。

拒绝带账号密码的 URL、不跟随重定向）；发送异步化，不阻塞分析线程。

## 6. 验收自检（部署完成 5 分钟）

1. `GET /api/system` 返回 backend 与摄像头状态
2. 添加一路摄像头 → 启动 → `GET /api/cameras/{id}/snapshot` 有画面
3. 画安全区 + 加 enter 规则 → 人进入 → 事件出现且 `has_video=true`
4. 事件页 ▶ 能播 H.264 视频；`GET /api/events/{id}/video` 返回 video/mp4
5. 报表页有当日折线与小时分布
6. 配置一个告警渠道后，手动制造事件，渠道收到统一文案
7. 摄像头页"实时画面"能出 WebRTC 画面（延迟约 1 秒）
