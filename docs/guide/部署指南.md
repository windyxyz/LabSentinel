# LabSentinel 部署指南

> 面向对象：实验室管理员/运维，以及需要源码构建的开发者。
> 照着做完即可获得：Web 端看实时画面与事件、按需配置告警渠道、按需开启人脸模块。
> 环境变量常用清单见根 [README.md](../../README.md)；安装/升级/卸载见
> [安装与卸载](安装与卸载.md)。

## 0. 部署形态选择

| 形态 | 适用 | 说明 |
|---|---|---|
| **安装包 setup.exe（推荐）** | Windows 单机、标准安装体验 | 双击安装（中英双语、仅我/所有用户双模式）；开始菜单/桌面快捷方式；升级自动 `--archive` 归档、装后 `--selftest-http` 探活；卸载走「设置 → 应用」 |
| **发布包 zip** | Windows 单机、免安装 | 解压 → 双击 `LabSentinel.bat`；包内自带模型/ffmpeg/onnxruntime/前端，无需 Python/Node；升级/回滚用 `--archive/--rollback` |
| **源码运行** | 需要改代码/自建模型 | Node 构建前端 + Rust `cargo run -p ls-server`；Python 仅用于资产准备/验收脚本（开发工具） |
| **Linux 原生** | 服务器/工控机 | Rust 单二进制 + systemd（见 §2）；模型/前端随构建产物 |
| ~~便携包（嵌入式 Python）~~ | 已退役 | ADR-0011 过渡期结束（2026-11-14）；旧版本仍可从历史 Release 下载，不再更新 |

单端口模式：`npm run build` 后 Rust 直接托管 `web/dist`（`LS_WEB_DIST` 可覆盖），
浏览器只访问 `http://127.0.0.1:8000`，前端路由刷新不 404，无需 Vite/Node 常驻。
缓存策略：`/assets/*`（内容 hash）一年 immutable；`index.html`/路由回退 no-cache；
其余静态 1h；文本响应 ≥1KB gzip（视频/zip/截图不压，Range 优先）。

## 1. Windows 源码部署

### 1.1 前置

- Windows 10/11 x64
- Rust stable（`rustup` / `cargo`）；Node 20+（仅构建前端）
- Python 3.12（仅 `scripts/prepare_rust_assets.py` 等开发工具使用；运行不需要）
- 磁盘：代码 + 模型约 1GB；事件截图/视频另计（每事件约 8MB 视频）
- 端口：8000（API/前端，默认仅本机可写）、127.0.0.1:1984（go2rtc 控制面，仅回环）、
  8555（go2rtc WebRTC 媒体面 UDP/TCP）

### 1.2 获取代码与前端构建

```bash
git clone <本仓库>
cd 监控识别
cd web && npm ci --registry=https://registry.npmmirror.com && npm run build && cd ..
```

模型不随仓库分发，二选一：
- **直接下载**：`python scripts/prepare_rust_assets.py`（按哈希锁拉取基础模型/PPE/ffmpeg/onnxruntime）
- **自己训练/导出**：按 [tools/README.md](../../tools/README.md) 执行
  `download_datasets.py → train_ppe.py → export_onnx.py`，产物放 `models/` 或 `m0-spike/`

### 1.3 运行

```bash
# 开发热更新（可选）：cd web && npm run dev   # Vite 5173，API 代理到 8000
cd engine-rs
cargo run -p ls-server -- --launch
# 或使用仓库根 一键启动.bat（自动注入 web/dist、模型与 ORT 路径）
```

等价的环境变量（全部可省略）：

```bat
set LS_WEB_DIST=web\dist
set LS_DATA_DIR=.data
set LS_MODEL_PATH=m0-spike\yolo11n.onnx
set LS_PPE_MODEL=m0-spike\yolo11n_ppe.onnx
set ORT_DYLIB_PATH=tools\onnxruntime\onnxruntime.dll
```

### 1.4 配置

优先在网页端完成（设置/告警配置/模型管理，保存即生效）。需要环境变量时：
`LS_ADMIN_TOKEN`（局域网必设）、`LS_HOST`、`LS_PORT`、`LS_MODEL_PATH`、
`LS_VLM_URL/KEY/MODEL` 等，见根 README 表格。**不需要**编辑任何配置文件。

### 1.5 生产化（可选）

- 单端口：Rust 托管 `web/dist`，只开 8000
- 开机自启：任务计划程序/WinSW 指向 `labsentinel-server.exe`（见 `deploy/windows/`）
- 防火墙放行 8000/TCP、8555/UDP（WebRTC 媒体）；1984 只绑回环，**不要**对外放行
- 反向代理/HTTPS 见下节

### 反向代理/HTTPS 与安全头

服务端自带基础安全响应头（nosniff/DENY/no-referrer/Permissions-Policy/CORP），
CSP 默认不发送——首次启用建议先 Report-Only：

```env
# LS_CSP=default-src 'self'; connect-src 'self' ws: wss: http://127.0.0.1:*
# LS_CSP_REPORT_ONLY=1
```

Nginx 最小反代示例（HSTS 由代理层加）：
```nginx
server {
    listen 443 ssl;
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
    }
    add_header Strict-Transport-Security "max-age=31536000" always;
}
```

### 1.6 常见问题（Windows）

| 现象 | 原因/处理 |
|---|---|
| 浏览器播不了事件视频 | 事件视频由 ffmpeg libx264 生成；确认包内/`LS_FFMPEG` 指向的 ffmpeg 可用，失败会回退 mp4v（ffplay 可播） |
| 实时画面一直"重连中" | go2rtc 未启动 / 1984 被防火墙拦 / 用 IP 而非 localhost 时 mDNS 候选失败 |
| 分析结果始终为空 | 未选择模型（「模型管理」）；或区域/规则未配置 |
| npm 安装超时 | 加 `--registry=https://registry.npmmirror.com` |

## 2. Linux 原生部署

Docker 路线已终止；Linux 用 Rust 单二进制 + systemd：

```bash
# 构建（任一 Linux 主机；交叉产物需对应工具链）
cd engine-rs && cargo build --release -p ls-server && cd ..
cd web && npm ci && npm run build && cd ..

# 目录（示例）
sudo install -d /opt/labsentinel/{web,models}
sudo cp engine-rs/target/release/labsentinel-server /opt/labsentinel/
sudo cp -r web/dist/* /opt/labsentinel/web/
sudo cp m0-spike/yolo11n.onnx /opt/labsentinel/models/   # 有 PPE 模型一并复制
sudo install -d -o labsentinel -g labsentinel /var/lib/labsentinel/data
sudo cp deploy/systemd/labsentinel.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now labsentinel
```

- 服务以 `labsentinel` 用户运行（需先创建用户/组）；数据在 `/var/lib/labsentinel/data`
- 可覆写配置放 `/etc/labsentinel/config.env`（EnvironmentFile，已预置）
- 局域网暴露：`LS_HOST=0.0.0.0` + `LS_ADMIN_TOKEN=<随机>`
- ffmpeg/onnxruntime：把 `tools/ffmpeg/ffmpeg` 与 `libonnxruntime.so` 放进可访问路径，
  通过 `LS_FFMPEG` / `ORT_DYLIB_PATH` 指定

## 3. 摄像头接入

> **现场实施一条龙**（预检→接线→区域→告警→24h）见 [摄像头接入Runbook](摄像头接入Runbook.md)。

### 3.1 发现助手（任务113）

不知道摄像头 IP/RTSP 路径时：「摄像头」页 → 添加表单下方**发现摄像头（局域网）** →
搜索（WS-Discovery/ONVIF，UDP 3702 组播）→ 对结果"探测"确认 RTSP 口与编码 →
选品牌模板**填入表单**，把占位的 `用户名:密码` 改成真实账号（建议子码流 102/subtype=1）。
搜不到的常见原因：跨网段、摄像头未开 ONVIF、防火墙拦组播、AP 隔离——此时手输模板即可。
助手只读探测，不会自动添加或启动摄像头。

| 品牌/来源 | RTSP 地址模板 | 说明 |
|---|---|---|
| 海康威视 | `rtsp://用户名:密码@IP:554/Streaming/Channels/101`（主码流）/ `102`（子码流） | 分析建议用子码流（720p） |
| 大华 | `rtsp://用户名:密码@IP:554/cam/realmonitor?channel=1&subtype=0`（主）/ `subtype=1`（子） | |
| 宇视 | `rtsp://用户名:密码@IP:554/media/video1` | |
| 手机模拟 | 手机装"IP 摄像头"类 App，取局域网 RTSP 地址 | 联调用；务必用 5GHz 局域网 |
| 视频文件 | 直接填文件路径，类型选"视频文件" | 演示用；`LS_FILE_LOOP=true` 可循环 |

注意事项：
- 摄像头编码建议 **H.264**（浏览器 WebRTC 直通）；HEVC 需 go2rtc 转码（`ffmpeg:` 源加 `#video=h264`）
- 分析帧率默认 5 FPS/路，`LS_ANALYSIS_FPS` 可降；多路并发能力见历史压测记录
- 摄像头账号建议用只读/子码流专用账号

### 3.1 USB 摄像头 / OBS 虚拟摄像头（联调）

没有真实 IP 摄像头时，可用本机 USB 摄像头或 OBS 虚拟摄像头验证设备链路。
当前版本不会自动枚举 DirectShow 设备：在「摄像头」页选 **USB** 类型后手动填写设备索引
（`0` 通常是第一个物理摄像头；OBS 虚拟摄像头通常是下一个索引）。枚举接口会明确提示
“无法自动枚举”，不影响 RTSP/视频文件/图片文件夹接入。

```bat
:: 开发调试：枚举可打开的索引并保存首帧（训练工具链，Python 仅作开发工具）
python tools\list_cameras.py --snapshot-dir logs\cam_probe

:: 用 OBS Virtual Camera 播放演示视频（需 OBS 虚拟摄像头驱动 + pyvirtualcam）
python tools\virtual_cam_feed.py --video m0-spike\data\lab-walk-24076.mp4
```

然后在「摄像头」页添加：类型 **USB**、设备索引填 `0`/`1`（以枚举结果为准）。
服务端把索引交给 ffmpeg dshow 取流；USB 常返回 `fps=-1`，平台按 30 兜底。

注意：
- OBS 虚拟摄像头只用于联调，**不能替代真实 RTSP 24h 验收**；
- 物理摄像头黑屏先检查系统隐私开关/物理遮挡；
- `virtual_cam_feed.py` 依赖 `pyvirtualcam`（`pip install pyvirtualcam`），不要与真实摄像头验收同时跑。

## 3.5 管理鉴权（可选）

绑定非回环地址（`LS_HOST=0.0.0.0`）时**必须**设置 `LS_ADMIN_TOKEN`，否则拒绝启动。
本机使用可留空（免鉴权）：

```ini
LS_ADMIN_TOKEN=your-secret-token    # 环境变量或 .env；为空即不启用
```

- 启用后**所有写操作**（POST/DELETE：加删摄像头/安全区/规则、事件处置、死信重发、维护清理、人脸注册删除）
  需带请求头 `X-Admin-Token: <token>`，否则 401
- `GET /api/system` 永不拦截（健康检查）；读操作默认放行，`LS_AUTH_READ_PROTECTED=true` 可一并保护
- Web 端：在「设置 → 管理令牌」填写（仅存浏览器 localStorage），401 时会有明确提示
- WS 实时推送：令牌经 `Sec-WebSocket-Protocol: bearer.<token>` 或 `Authorization: Bearer` 传递；
  读保护开启时 WS 与 HTTP 同口径（支持 Origin 同源校验）
- 部署验收：`POST /api/alert-test` 会逐渠道自检（含 401 路径验证）

## 4. 告警渠道配置

**推荐：网页端「告警配置」页**（管理员）——按渠道卡片填写 Webhook/Key/邮箱授权码，点「保存」
立即生效，无需改 `.env` 或重启；支持单渠道「发送测试」。密钥只保存在本机数据库且不回显，
留空保存=保持原值，「清除」=回退启动时 `.env`。下表保留 `.env` 变量口径，供高级/批量部署使用。

| 渠道 | 去哪拿 | 配置项 | 备注 |
|---|---|---|---|
| 应用内 | 无需配置 | — | Web 端右上角 WS 状态，事件实时弹出 |
| 企业微信 | 群 → 添加群机器人 → 复制 Webhook | `LS_WECOM_WEBHOOK` | 仅 `qyapi.weixin.qq.com` |
| 钉钉 | 群设置 → 智能群助手 → 添加机器人 → 自定义 | `LS_DINGTALK_WEBHOOK` | 仅 `oapi.dingtalk.com` |
| 飞书 | 群设置 → 群机器人 → 自定义机器人 | `LS_FEISHU_WEBHOOK` | 仅 `open.feishu.cn` |
| 微信（Server酱） | sct.ftqq.com 微信扫码登录 → SendKey | `LS_SERVERCHAN_SENDKEY` | 推送到微信服务号 |
| 微信（PushPlus） | pushplus.plus 微信登录 → token | `LS_PUSHPLUS_TOKEN` | 公众号消息 |
| QQ（Qmsg酱） | qmsg.zendee.cn 登录 → key | `LS_QMSG_KEY` + `LS_QMSG_QQ` | 需加机器人好友；QQ 侧风控严 |
| 邮箱 | QQ 邮箱：设置 → 账户 → 开启 SMTP → 授权码 | `LS_SMTP_HOST/PORT/USER/PASS` + `LS_ALERT_EMAIL_TO` | 端口 465 走 SSL |

| 通用 Webhook | 自建服务（n8n/自研平台/局域网网关） | `LS_WEBHOOK_URL`（+`LS_WEBHOOK_SECRET`/`LS_WEBHOOK_ALLOW_HTTP`/`LS_WEBHOOK_TIMEOUT_S`） | HMAC 签名，见下 |

**通用 Webhook（任务67）**：POST JSON `{"version":1,"title":"LabSentinel 级别N告警","text":"…","level":N,
"ts":"…","source":"labsentinel","event_id":..,"camera_id":..,"type":"..","detail":".."}`；
配置 `LS_WEBHOOK_SECRET` 后每个请求带 `X-LS-Signature: sha256=<hex hmac_sha256(secret, 原始body)>`、
`X-LS-Event: alert`、`X-LS-Timestamp`。默认仅允许 https；自建 http 服务设 `LS_WEBHOOK_ALLOW_HTTP=true`。
接收方验签（原始 body 字节，不要先 json 再重序列化）：

```python
import hmac, hashlib
ok = hmac.compare_digest(
    hmac.new(SECRET.encode(), raw_body, hashlib.sha256).hexdigest(),
    request.headers["X-LS-Signature"].removeprefix("sha256="))
```

**按渠道过滤（任务86）**：`LS_ALERT_FILTERS`（JSON）可让指定渠道只收特定级别/类型，例如
`{"email":{"min_level":3},"wecom":{"types":["enter_no_ppe"]}}`——email 只收 L3+，
企微只收未穿实验服。被过滤的事件不建投递行（与"未配置"语义一致）；`alert-test` 不受过滤影响。

拒绝带账号密码的 URL、不跟随重定向）；发送异步化，不阻塞分析线程。

## 5. 人脸比对合规自查清单（开启前逐条确认）

依据《人脸识别技术应用安全管理办法》（2026-06-01 施行），详见
[20-research/00-synthesis.md §7](../archive/20-research/00-synthesis.md)：

- [ ] 已就人脸信息的收集、使用**单独取得**被识别人员同意（注册接口强制 `consent=true`，记录落 `face_consents` 表）
- [ ] 采集现场设置**显著的人脸识别提示标识**
- [ ] 明确告知处理目的、方式、保存期限，并提供删除渠道
- [ ] 人脸信息不出境、不用于考勤等未告知用途
- [ ] 处理超过 **10 万人**人脸信息已依规备案
- [ ] 定期核查人员库与同意记录，离职/撤回同意者及时删除（`DELETE /api/face/persons/{subject}`）
- [ ] 一键清除演练过：`DELETE /api/face/persons/all`（人员库 + 同意记录）
- [ ] 人脸数据目录（`data/compreface-db`）已纳入备份/销毁流程

## 6. 验收自检（部署完成 5 分钟）

1. `GET /api/system` 返回 backend 与摄像头状态
2. 添加一路摄像头 → 启动 → `GET /api/cameras/{id}/snapshot` 有画面
3. 画安全区 + 加 enter 规则 → 人进入 → 事件出现且 `has_video=true`
4. 事件页 ▶ 能播 H.264 视频；`GET /api/events/{id}/video` 返回 video/mp4
5. 报表页有当日折线与小时分布
6. 配置一个告警渠道后，手动制造事件，渠道收到统一文案
7. 摄像头页"实时画面"能出 WebRTC 画面（延迟约 1 秒）
