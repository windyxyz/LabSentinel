# LabSentinel 运维手册（部署单位日常操作一本通）

> 面向：负责让系统**持续跑着**的管理员/值班人员——不需要会开发。
> 安装步骤见 [安装与卸载](安装与卸载.md)；部署见 [部署指南](部署指南.md)。
> 本文从"装完之后"开始。**运行形态**：Rust 单二进制（`LabSentinel.bat` 启动），
> 无 Python/Node/数据库依赖。

## 1. 十分钟上手

1. 安装：解压 `labsentinel-rust-<版本>-<日期>.zip` → 双击 `LabSentinel.bat`（无需安装）。
2. 启动：双击 `LabSentinel.bat` → 约 2–5 秒后浏览器自动打开控制台。
3. 换成真实摄像头：「摄像头」页 → 添加（RTSP 填地址；USB 手动填索引；或选图片文件夹）。
4. 画安全区：「安全区配置」页 → 选摄像头 → 多边形圈出要监控的区域。
5. 加规则：「安全区配置」页 → 该摄像头加 `enter`（进入提醒）或 `enter_no_ppe`（未穿实验服告警）。
6. 启动摄像头：摄像头行点「启动」→ 仪表盘应看到 running 与实时事件流。
7. 测告警：「设置 → 通知与告警 → 发送测试」；先在「告警配置」页配好至少一个渠道。
8. 确认闭环：「事件查询」页看到事件 → 处置（确认/误报/忽略）。

## 2. 每日/每周巡检清单

打开**仪表盘**，逐项核对（全部只读，2 分钟）：

| 看什么 | 正常 | 需处理 |
|---|---|---|
| 今日事件 / 未处置 | 未处置不过夜 | 未处置持续累积 → 排值班处置流程 |
| 摄像头状态列 | running + fps 正常 | error（看红字 last_error）/ 画面停滞 / 重连次数上涨 → §4 |
| **磁盘**卡 | 绿色 + 剩余充足 | 变红「磁盘不足，将触发紧急清理」→ 立即 §9 |
| 实时通道 | 已连接 | 断开重连不恢复 → §6 |

每周加做（3 分钟）：

- 「报表」页 → **处置质量卡**：看未处置/误报率；持续偏高 → 误报池标注/模型迭代
  （[标注与模型迭代手册](../标注与模型迭代手册.md)）；
- 「设置 → 通知与告警」→ 查**投递失败**列表（有失败点「重发」，反复失败 → §5）；
- `GET /api/health/ready`（503 时 `checks` 逐项给原因）与 `GET /api/diagnostics/summary`
  的 `recent_errors` 有无集中报错（§6）；
- 保留策略预演：`GET /api/maintenance/preview` 看下次清理会删多少（只读不删）。

## 3. 启动 / 停止 / 自启

- **启动**：双击 `LabSentinel.bat`（数据默认 `%LOCALAPPDATA%\LabSentinel\data`）；
- **停止**：网页「设置 → 服务控制 → 停止服务…」，或任务管理器结束 `labsentinel-server.exe`；
- **单实例**：`--launch` 会探测端口，已在运行时只打开浏览器，不会起第二个服务；
- **端口**：默认 8000；改 `LS_PORT`（写在 `LabSentinel.bat` 里或系统环境变量）；
- **开机自启**：`Win+R` → `shell:startup` → 放入 `LabSentinel.bat` 快捷方式；
- **局域网访问**：`LS_HOST=0.0.0.0` + `LS_ADMIN_TOKEN=<随机>`，防火墙放行端口。

### 3.1 端口被占用 / 启动失败

```bat
netstat -ano | findstr ":8000" | findstr "LISTENING"   :: 最后一列是 PID
taskkill /PID <pid> /F
```

- `--launch` 发现端口已被监听时会直接打开浏览器（认为已有实例）；若打开的页面不是
  LabSentinel，换 `LS_PORT` 或结束占用进程；
- 启动窗口报错时保留输出；数据目录不可写、模型文件损坏会给出明确原因。

## 4. 摄像头排障

> 首次接线/换机重接，走 [摄像头接入Runbook](摄像头接入Runbook.md)（预检→区域→告警→24h 一条龙）。

「摄像头」页状态列会直接给出可读原因（红字=最近错误，自动脱敏不含密码）：

| 现象 | 先查 | 处理 |
|---|---|---|
| error + "打开失败" | RTSP 地址/账号（海康/大华模板见[部署指南 §3](部署指南.md)） | 改地址；USB 换索引；文件确认路径存在 |
| 画面停滞 Ns | 网络抖动 / 摄像头掉线 | 看重连次数是否在涨；自动重连成功会恢复 running |
| 重连次数持续上涨 | 子码流带宽 / 交换机 | 分析建议用**子码流（720p）**；编码用 H.264（H.265 需转码） |
| USB 找不到设备 | 隐私挡板 / 被会议软件占用 | 关 Zoom/腾讯会议；手动换索引；开发环境用 `tools\list_cameras.py` 探测 |
| 夜间大量误报 | 红外画面分布偏移 | 调 `LS_PPE_CONF`/`LS_PPE_WEARING_CONF`；长期问题走数据飞轮（[手册](../标注与模型迭代手册.md)） |

**USB 选择**：当前版本不自动枚举设备，需手填索引（0/1/2…）；索引是 DirectShow 顺序，
拔插/驱动更新后可能变化。

### 4.1 worker 退出自动恢复（守护）

状态列出现 `重试中（第 N 次）` = 守护正在按 1/5/30/60s 退避自动重启；显示
`自动重启失败，请检查` = 连续失败已达上限，摄像头转 error——先按上表排查根因，
修好后手动点「启动」即重新纳入守护。

### 4.2 摄像头分组

「摄像头」页可按组筛选/整组启停/多路勾选批量启停（≤100 路/次）。巡检时可按组核对运行数
（分组下拉显示"count 路 / running 运行"）。分组名 ≤32 字符，空=未分组。

### 4.3 规则模板库

多实验室同款规则用「规则模板」保存/套用（重名 409；套用时同类型+同时间窗自动跳过）。
巡检：新装/换季调整时优先改模板再套用，避免逐路手改导致口径漂移。

### 4.4 规则日历条件

规则可配"生效星期 + 仅假期 + 时间段"（[接入 Runbook](摄像头接入Runbook.md) §3 有操作步骤）。
巡检关注：假期前后检查「日期例外」表是否需要更新（法定假期标 holiday、调休补班标 workday）；
发现某路"该响不响"先看规则的星期/假期/时间窗三条件再查模型（判定顺序：星期→假期→时间窗→冷却）。

## 5. 告警排障

- 看渠道状态：`GET /api/alerts/status`（各渠道 configured/投递计数）；
- **一键自测**：「设置 → 通知与告警 → 发送测试告警」（未配置渠道会明确标注，不产生失败记录）；
- **失败重发**：投递失败列表 → 「重发」；系统有 1s/4s/15s 三次退避重试，仍失败进死信；
- **操作审计**：报表页「操作审计」区查所有写操作（谁/何时/做了什么/结果），仅管理员可见；
- **维护窗口**：「设置 → 通知与告警 → 告警静默」——全局/按摄像头/按级别/按类型，1h–7 天，
  到期自动恢复；静默期事件照常记录，仅外部渠道不推送；
- 七个厂商渠道申请方式见[部署指南 §4](部署指南.md)；**自建服务**用通用 Webhook（带 HMAC 验签，
  [验签方法](部署FAQ.md)）；
- 邮件渠道高频坑：QQ 邮箱必须用**授权码**（不是登录密码）、端口 465=SSL；
- 全部渠道没反应：先看「实时通道」是否已连接（应用内推送正常=派发器活着），再逐渠道自测。

### 5.1 值班桌面通知

值守人员浏览器打开面板 → 仪表盘点「开启桌面通知」授权；之后页面最小化时 L2/L3 事件弹
系统通知（L1 不弹、同源 10s 去重、勾选可暂停）。PWA"安装成应用"仅 localhost/HTTPS 可用
（SW 限制）；外发告警不受此影响。

## 6. 日志与诊断

| 内容 | 位置 |
|---|---|
| 服务端日志 | 启动窗口标准输出；Linux 用 `journalctl -u labsentinel -f` |
| 运行中聚合状态 | `GET /api/diagnostics/summary`（版本/时长/计数/磁盘/最近 20 条 ERROR，已脱敏） |
| 单事件证据 | 事件详情 →「下载证据包」（event.json+截图+视频+README） |

- 报障三件套：`/api/system` 的 version、出错请求的 `request_id`（响应头/错误体）、
  `/api/diagnostics/summary` 输出；在启动控制台/journalctl 按 request_id 检索上下文；
- 数据库出现 `labsentinel.db-wal`/`-shm` 属正常，**不要手删**（[WAL 说明](部署FAQ.md)）。

## 7. 备份 / 恢复 / 迁移

- **运行中备份**：`POST /api/backups/run`（SQLite 一致快照；响应给出备份文件位置），
  或网页「设置 → 数据管理」导出配置 JSON（摄像头/区域/规则，默认脱敏密码）；
- **配置级迁移**：导出 JSON → 新机导入（merge 跳过同名 / replace 清空后导入，需勾选确认）；
  批量部署多路时改 JSON 后导入，免逐路手填；
- **多路快速套用**：「安全区配置」页 → 复制到其他摄像头（勾选目标，规则按区域名映射）；
- **整机迁移**：新机解压同版本 → 停服务 → 把备份恢复到 `data\` → 启动；
- **只拷 `.db` 文件不行**（会丢 WAL 未合并数据）。

## 8. 升级 / 回滚

> **更新提示**：`LS_UPDATE_MANIFEST_URL` 指向静态 JSON 清单后，仪表盘"版本"卡会在有新版本时
> 提示（字符串不等即提示；缓存 1h；绝不自动下载/安装）。升级仍按以下手动流程。

```bat
rem 1) 网页「设置 → 服务控制」停止服务
rem 2) 归档当前版本（安装根下生成 versions\<版本>\，自动排除 data/）
cd /d D:\Apps\LabSentinel
labsentinel-server.exe --archive .

rem 3) 解压新 zip 覆盖程序文件（保留 data\ 与 versions\）
rem 4) 双击 LabSentinel.bat
```

- **回滚**：`labsentinel-server.exe --rollback .`（选 `versions\` 中除 current.txt 外的最新一版）；
- 升级后页面若仍旧版：强刷 Ctrl+F5（index.html 已是 no-cache）；
- 回滚后仍异常：用升级前的数据备份恢复（数据库结构与版本不匹配时）。

## 9. 容量与性能

- 磁盘预警：仪表盘「磁盘」卡；低于 `LS_DISK_MIN_FREE_GB`（默认 5GB）变红并将自动紧急清理旧事件；
  「按当前增速约 N 天」是**估算值**（近 7 天日均）；
- 保留期：`LS_RETENTION_EVENTS_DAYS`（默认 180 天）/`LS_RETENTION_POOL_DAYS`（90 天）；
- 分析帧率：`LS_ANALYSIS_FPS`（默认 5/路）；多路能力需真实摄像头压测；
- 磁盘增长主要来自事件截图/视频（单事件约 8MB 级）；视频存证可在规则层面控制告警量；
- 何时加机器：磁盘卡持续低于阈值且清理后快速回落 / 帧率明显下降 → 降路数或拆分实例。

## 10. 安全与合规

- **管理令牌**：设 `LS_ADMIN_TOKEN` 后所有写操作需令牌；可选 `LS_AUTH_READ_PROTECTED=true`
  连读接口也保护；网页「设置 → 管理令牌」只存浏览器本地；
- **传输**：跨网段/公网访问走反向代理 HTTPS（[部署指南 §1](部署指南.md)），不要裸露 8000 到公网；
- **人脸比对默认关闭**：开启前必读[合规章节](部署指南.md)（单独同意+现场标识+留痕），一键清除
  `DELETE /api/face/persons/all`；
- 诊断输出已脱敏（令牌/密码/密钥/URL 凭证一律 `***`），但**事件文本**（含区域名等）会保留
  ——对外发送前自行确认可接受。

## 11. 故障速查表

| 症状 | 先查 | 然后 |
|---|---|---|
| 页面打不开 | `netstat -ano \| findstr :8000`；启动窗口报错 | §3 端口/单实例 |
| 摄像头 error / 画面停滞 | 状态列红字 last_error | §4；重连次数在涨=网络问题 |
| 有摄像头但无事件 | 是否 running、是否画了安全区+加了规则 | 仪表盘实时通道；`camera_soak.py` 采样验证 |
| 告警不发 | `/api/alerts/status` + 一键自测 | §5；失败列表重发；检查退避死信 |
| 磁盘满 | 仪表盘磁盘卡 / `maintenance/status` | §9：调低保留天数 → `maintenance/preview` 预演 → cleanup |
| 升级后页面旧 | 强刷 Ctrl+F5 | [缓存说明](部署FAQ.md)；检查代理缓存 |
| 页面报错带 request_id | 启动窗口/journalctl 按 id 检索 | §6 诊断报障 |

## 12. 发布后 24h 观察清单（运维视角）

> **挂机前置**：24h 验收机的电源计划若会自动睡眠，务必在配置开 `LS_KEEP_AWAKE=true`
> （服务运行期间阻止睡眠/硬盘休眠，不改电源计划，停止服务即恢复；`/api/system` 的
> `keep_awake.active=true` 可确认生效）。它**不阻止**用户注销或 Windows 更新重启。
> 对齐 [摄像头24h验收清单](摄像头24h验收清单.md)，从运维角度关注：

- 每隔 2–4h 扫一遍 §2 巡检项（重点：各路 fps 是否稳定、重连次数、磁盘斜率）；
- **未处置提醒**：L3 超 15 分钟未处置会经现有渠道再提醒一次（⏰ 前缀，每事件一次）；
  间隔/级别见 `LS_ESCALATE_*` 配置，状态看 `/api/escalation/status`；
- **误报风暴处置**：事件查询页勾选多条 → 批量确认/误报/忽略（误报截图自动入标注池）；
- **Prometheus/Grafana 接入**：`GET /api/metrics` 输出标准 Prometheus 文本指标
  （up/uptime/cameras/fps/frame_age/events/deliveries/disk/db/schema_version）。
- **事件搜索**：事件查询页支持关键词与今天/昨天/近 7 天/近 30 天预设；
- `tools/camera_soak.py --all --duration 24h` 可对**全部路**做 24h 采样（开发工具，
  产物 CSV+JSON；接入前先 `--preflight`）；
- **回滚阈值**：服务崩溃重启超过 2 次、数据目录增长明显异常（>预估 2 倍）、告警渠道整体失败
  超过 1h —— 先回滚到上一版（§8），再排查；
- 24h 结束：导出证据包（报表页）留档，核对事件数与人工抽查是否一致。
