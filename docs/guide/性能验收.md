# 多路性能验收

基准使用随包 FFmpeg、go2rtc、ONNX Runtime、YOLO11n 和实验服模型。视频源是 1920×1080、12 FPS 的 H.264 RTSP。分析保持 5 FPS，工作帧缩放为 1280×720。合成片段按 4 秒分段，依次是空场、有人、低光、远景和运动测试图。

## 同参数运行

在 `engine-rs` 下按 [Windows 构建配方](../../AGENTS.md#4-本机构建与测试配方windows-中文路径必读) 配置工具链。将 `$stage` 指向已解包的 Windows 发行目录，将 `$results` 指向结果目录。

```powershell
$env:LS_INSTALL_DIR = $stage
$env:LS_FFMPEG = Join-Path $stage 'tools\ffmpeg\ffmpeg.exe'
$env:ORT_DYLIB_PATH = Join-Path $stage 'onnxruntime.dll'
$env:LS_PPE_MODEL = Join-Path $stage 'models\yolo11n_ppe.onnx'
$env:LS_INFER_BACKEND = 'ort'
$env:LS_BENCH_EP = 'cpu'
$env:LS_BENCH_CAMERAS = '4'
$env:LS_BENCH_SECONDS = '30'
$env:LS_BENCH_REPORT = Join-Path $results 'cpu-4.json'
$env:LS_BENCH_PID_FILE = Join-Path $results 'cpu-4.pid'
cargo +stable-x86_64-pc-windows-gnu test --release -p ls-server --all-features tests::performance::windows_rtsp_benchmark -- --ignored --nocapture
```

完整短测用 `cpu` 和 `dml` 各运行 1、4、9 路。为每组指定独立的报告和 PID 文件。用 `LS_BENCH_OUTAGE=1` 加入断流与恢复。在另一个 PowerShell 窗口用以下命令同步采样进程树。

```powershell
..\scripts\sample_benchmark.ps1 -PidFile $env:LS_BENCH_PID_FILE -OutputCsv (Join-Path $results 'cpu-4-resources.csv')
```

识别质量使用同一视频的确定性离线回放，分别记录各场景有人判定和 PPE 状态。

```powershell
$env:LS_BENCH_REPORT = Join-Path $results 'scene-truth.json'
cargo +stable-x86_64-pc-windows-gnu test --release -p ls-server --all-features tests::performance::windows_scene_truth_replay -- --ignored --nocapture
```

报告包含每路有效分析 FPS、模型实际运行次数、DirectML 调用、重连和分阶段 p50／p95／p99。`analysis_after_read_ms` 从完成读取原始帧到规则分析完成。`read_wait_ms` 包含等待 FFmpeg 提供下一帧的时间。各路延迟窗口最多保留最近 1,200 帧，总计数覆盖测量全程。CSV 聚合基准及其子进程的 CPU、工作集、私有内存和可用的 GPU 引擎计数器。

用包含 `vulkan` 目录的验收包，将 `LS_BENCH_EP` 设为 `auto_vulkan` 并保留 `--all-features`，可测试 Vulkan。报告校验各路的人员与 PPE 设备、Vulkan 调用计数以及实际同帧运行。`person_ppe_ms` 包含同一帧中人员检测和 PPE 阶段的累计耗时，含预处理、裁剪、模型执行和输出处理，仅统计实际调用 PPE 的帧。`vulkan_run_ms` 是 ncnn 执行与输出读取用时，只统计运行了 Vulkan 的帧。`directml_lock_wait_ms` 记录 DirectML 调度等待，ncnn 驱动内部等候仍计入 Vulkan 执行时间。

每组分位数附带 `samples`。PPE 子阶段为 `ppe_full_frame_ms`、`ppe_crop_ms`、`ppe_coat_confirmation_ms` 和 `ppe_close_mask_ms`。只在该阶段实际执行的帧纳入统计。同一帧有多个裁剪时，按裁剪耗时总和记录一个样本。某阶段没有运行时返回 `null`。各阶段可能取自不同帧，可用同帧总耗时衡量端到端延迟。

排查首次执行延迟时，可为 Rust RTSP 基准设置 `LS_BENCH_WARM_PPE=1`。预热等待每路完成至少一次人员与 PPE 同帧推理，随后清空滚动窗口。报告的 `warmup_cameras` 保存清空前的数据，`cameras` 保存后续固定时长的数据。

开启实时采集的版本中，`capture_queue_ms` 从服务端读完原始帧到分析线程取走帧，`analysis_frame_age_ms` 从服务端读完帧到规则分析完成，`capture_overwritten_frames` 记录被后到原始帧覆盖的待分析帧。源设备编码、网络传输及 FFmpeg 内部解码耗时需用端到端视频时间戳另测。对照 `ceb1ebb` 时使用两版共有的 `analysis_after_read_ms`，同时在新版记录等待、覆盖、分析完成时的帧龄和关键事件真值。

在「摄像头 → 分析码流」可选直连主码流、与预览共享本机中继或独立子码流。使用子码流时，选与预览相同视角及宽高比并复核画面叠加框。对照时从 `perf.analysis[].input` 确认是 `main`、`relay` 或 `substream`。分别断开中继或配置不可用的子流，确认自动回到主码流且规则仍生效。

## 发行实例组合回归

从仓库根目录运行以下命令。暂存目录使用待验收的 Windows 发行包，输出目录每次另选一个新路径。脚本启动回环 RTSP、Rust 服务和 Chromium 值守大屏，保存逐路滚动统计、Windows 进程资源、定时断流恢复及真实事件录像播放记录。

```powershell
node web/scripts/soak_product.mjs --package $stage --out $results --backend auto_vulkan `
  --cameras 4 --seconds 90 --warmup 5 --sample 5 --outage-every 45 --outage-seconds 3 `
  --vlm-runtime $llamaRuntime --vlm-model $gguf --vlm-projector $mmproj --vlm-gpu-layers 99 --vlm-every 20
```

问答周期可按运行时延迟调整，`vision.jsonl` 保存模型、证据 ID、请求时段和各路分析计数差。启用该场景需要三项 VLM 路径，脚本将运行时和模型复制到验收目录。本机托管端口为 18680。9 路对照使用 `--cameras 9`，DirectML 回退对照使用 `--backend dml`。示例时长可按实际恢复情况调整，验收以用例覆盖和报告为准。

可用 `--gpu-id` 传入检测设置返回的 LUID，核对所选 CV 显卡与回退映射。VLM 的 `--vlm-device` 仍使用 llama.cpp 列出的编号，组合报告同时保存两者。

`samples.jsonl` 保存测量期间的滚动窗口，`report.json` 汇总断流、事件片段、系统事件和关停结果。输出目录内新增 `stop.requested` 可结束验收。Windows 事件和采样中见到的子进程在退出后重新核对。正式性能、跨显卡和准确度门槛按路线图 §6 判定。

## 2026-11-23 分项结果

Windows 11 专业工作站版 26300，AMD Ryzen AI 9 H 365，Radeon 880M 驱动 32.0.32015.16001。ffprobe 核验测试源为 20.000 秒、240 帧、1920×1080 H.264。

使用 go2rtc 提供同一隔离 RTSP 源，FFmpeg 客户端各解码 10 秒媒体时间并缩放，输出交给空复用器。下表耗时含握手及首帧等待。

| 并发 | FFmpeg 正常退出 | 每路输出帧 | 实际耗时范围 |
| --- | --- | --- | --- |
| 1 路 | 1/1 | 46 | 11.910 秒 |
| 4 路 | 4/4 | 46 | 11.822–11.894 秒 |
| 9 路 | 9/9 | 46–50 | 11.772–11.883 秒 |

完整 Rust 流程的 Release 依赖编译程序、Debug 基准程序和独立模型工具的 NumPy 模块均遇到 Windows 应用控制 4551。CPU／DirectML 整链数据、识别质量、4 路对比和 9 路长跑为空缺，待在可执行发行构建的 Windows 环境用同一场景补齐。
