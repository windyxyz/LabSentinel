## 二、复审发现（按严重度）

1. **发布硬阻塞未变**：真实 RTSP 摄像头 24h、模型止损线（Lab Coat≥60%、误报≤20%/天）；
   GitHub Actions 实际跑通、代码签名也未完成。这些不是再写功能能消除的。
2. **24h 运行保障缺口**：Windows 自动睡眠/硬盘休眠会让告警链中断（建议 #20 防休眠）；
   worker 线程退出后目前需人工点启动（任务 114）；误报率只能人工数（任务 102）；
   真机执行缺一份现场 Runbook（任务 99）。
3. **109/110 未做**：deploy.py 新机三坑、停止 PID 复用/冒烟清理，属于安装可靠性。
4. **发布卫生**：`api.py` 里 2 条 `TODO(任务87)` 已过期（审计早已由中间件实现），导致 release_check WARN；
   便携包 `app/server/app/__pycache__` 有 22 个 .pyc（应排除）；版本号 `0.1.0-m1` 与 `v0.1.0-alpha`
   口径已在发布报告注明“允许”，但最终 RC 前应统一。
5. **前端零自动化测试**：只有 build 冒烟；PWA/桌面壳上线前建议补 vitest（P3，不阻塞）。
6. **CI 仍是静态验证**：52 的 portable.yml 没在真实 runner 跑过；建议补 pytest+build workflow，
   但“实际跑通”需要 GitHub 远端（用户侧）。
7. **建议池的误判风险**：VLM/MQTT/插件都涉及新进程/新依赖/GPU 竞争，必须默认关闭、显式开启、
   不阻塞主链路；Rust/Electron/重型视觉与当前负载画像不匹配，维持否决。

## 六、风险与前置条件

- **VLM（124）**：与 DirectML 共享 GPU 可能拖慢推理；必须独立进程/单并发/默认关；
  无 Ollama 或模型时只做接口与假服务测试，不下载大模型。
- **MQTT（125）**：新增 `paho-mqtt` 依赖；密码进 .env 且加入诊断包脱敏清单；broker 不可达不能阻塞事件。
- **插件（126）**：插件=代码执行；默认禁用、启用弹权限清单、只用现有令牌子集；不进 git。
- **防休眠（123）**：只影响进程生命周期，不改用户电源计划；停止/退出恢复 ES_CONTINUOUS。
- **发布硬阻塞**：真实摄像头 24h、模型止损线、GitHub Actions 实跑、签名；本计划只能提供工具与证据，
  不能替用户完成硬件验收。
