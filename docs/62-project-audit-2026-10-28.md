## 一、结论先说

- 核心链路与"开箱即用"已就绪：便携包双击可用、首启自动播种 4 路演示、数据外置、安装/卸载/停止齐全。

## 二、旧启动脚本的去留决策（本次已落地）

| 入口 | 定位 | 处理 |
|---|---|---|
| 便携包 `启动.bat` / `安装.bat` / `停止.bat` / `卸载.bat` | **普通用户首选** | README/快速开始已置顶推荐 |
| `一键启动.bat` + `scripts/deploy.py` | 源码/开发模式；新机自动装环境 | **保留**；README 标注"开发模式"；新增：检测到便携包时提示；**没有 Python 时自动改为启动便携版** |
| `scripts/start-all.bat` / `stop-all.bat` / `health-check.bat` | 开发者三件套/排障 | 保留 |

这样既不会让普通用户看到一堆脚本，也不牺牲开发者/CI 能力。

## 三、本轮发现并修复

1. **`tools/preannotate.py` 预览图在中文路径下静默丢失**（`cv2.imwrite` 对非 ASCII 路径失败）。
   已改 `imencode + Path.write_bytes`，与 pipeline/make_demo/frame_sampler 统一；`--help` 正常。
2. **一键启动缺环境兜底**：新机没 Python 时只报错。现在若存在 `dist/portable/LabSentinel/启动.bat`
   会直接改启便携版；有 Python 时也会提示"普通用户优先用便携包"。
3. **便携包移动后演示摄像头路径失效**：播种时写的是绝对路径，换目录后找不到视频。
   `portable_launcher.py` 新增 `repair_media_paths()`：每次启动按文件名在 `media/` 重新定位（仅当原路径不存在）。
4. **README 两处陈旧**：源码部署写 Python 3.11+（实际 3.10+）；"首次播种由 deploy.py"对便携版不成立。
   已改为双路径说明。
5. （前序已修）SPA 回退不再吞未知 `/api/*`；便携首启空库/无 media 已由任务 47 补齐并实测。

### P2（优化/架构）

- **播种逻辑重复**：`deploy.py` 与 `portable_launcher.py` 各有一份 schema/seed/zones，容易漂移。
  建议抽成 `scripts/seed_demo.py`（或 server 内共享模块），deploy/portable 都调用，并加一个测试。
- **环境来源重复**：源码模式 `deploy.py` 与便携构建各装一套依赖；建议 CI 用同一 requirements/锁定版本，
  避免"开发能跑、便携包不能跑"。
- **无自动更新/版本检查**：便携包版本只写在 `app/VERSION`，无升级提示；可在 launcher 加"检查版本 JSON"（可选）。
- **日志无轮转**：`logs/server-*.log` 只追加；长期运行建议按大小轮转（或交给 retention）。
- **文档口径**：部分文档仍提 `D:\LabSentinel\m0-venv`，与项目 `.venv` 并存；建议统一"首选 .venv，m0-venv 为旧装兼容"。
- **人脸/多端**：CompreFace 未实测（需 Docker + 合规确认）；Android/iOS/HarmonyOS 仍是骨架/未构建。
- **桌面壳**：当前"本地服务 + 浏览器 + 快捷方式"已够开箱即用；Tauri/WinUI 壳只在需要独立窗口/托盘时再做。
