# LabSentinel 部署指南

> 面向对象：会装 Python、但第一次接触本项目的实验室管理员/运维。
> 照着做完即可获得：Web 端看实时画面与事件、按需配置告警渠道、按需开启人脸模块。
> 配置项完整清单见 [server/.env.example](../server/.env.example)。

## 0. 部署形态选择

| 形态 | 适用 | 优点 | 限制 |
|---|---|---|---|
| **便携包（推荐入门）** | Windows 单机开箱即用 | 双击即用，自带嵌入式 Python，无需装 Python/Node；数据在用户目录可控 | 体积大（安装后 ~716MB） |
| Windows 原生 | 单机、本机有摄像头/视频文件、要用 DirectML/NPU 加速、需要改代码 | 可用核显加速，部署最简单 | 需要自己装 Python |
| Docker（Linux） | 服务器长期运行 | 环境一致、开机自启 | 默认 CPU 推理；人脸模块也走 Docker |

本仓库两条路径都支持；Web 端构建产物是静态文件，服务端是单个 FastAPI 进程。
**便携包的安装/升级/卸载/数据位置/自启**：见 [59-portable-install.md](59-portable-install.md)；
打包方法见 [50-tasks/44-portable-runtime-builder.md](50-tasks/44-portable-runtime-builder.md)。

> **单端口模式（生产/打包推荐，任务43）**：`cd web && npm run build` 之后**只开 8000** 即可——
> 服务端自动托管 `web/dist`（可用 `LS_WEB_DIST` 指向其他目录），浏览器直接访问
> `http://127.0.0.1:8000`，前端路由刷新（如 /events）不 404；无需 Vite/Node 常驻。
> 开发时仍可另开 `npm run dev`（5173 热更新），互不影响。

## 1. Windows 原生部署

### 1.1 前置

- Windows 10/11 x64；Python **3.11+**（本仓库开发环境为 3.14）
- 磁盘：代码 + 模型约 1GB；事件截图/视频另计（每事件约 8MB 视频，见容量规划）
- 端口：8000（API）、5173（Web 开发服，生产可换 nginx 托管 dist）、1984（go2rtc，TCP+UDP）、8554（go2rtc RTSP，可选）

### 1.2 获取代码与模型

```bash
git clone <本仓库>
cd 监控识别
```

模型文件不随仓库分发，二选一：
- **直接下载**：yolo11n.onnx（人员检测，COCO 预训练）放置 `m0-spike/`
- **自己训练/导出**：按 [tools/README.md](../tools/README.md) 执行 `download_datasets.py → train_ppe.py → export_onnx.py`
  （实验服模型 `m0-spike/yolo11n_ppe.onnx`；类目顺序见任务 06 执行报告）

### 1.3 创建 venv 并装依赖

```bat
python -m venv D:\LabSentinel\m0-venv
D:\LabSentinel\m0-venv\Scripts\python.exe -m pip install -r server\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> 铁律：`supervision==0.25.1` 不可升级（0.26+ 移除 ByteTrack）；`onnxruntime` 与
> `onnxruntime-directml` 不可同装（Windows 用 directml 版，Linux/Docker 用普通版）。

### 1.4 配置

复制 `server/.env.example` 为 `server/.env`，按需修改（可全部留空先跑起来）。

### 1.5 一键启动

```bat
scripts\start-all.bat
```

会开三个窗口：go2rtc（1984）→ uvicorn（8000）→ vite dev（5173）。
浏览器打开 http://localhost:5173：
添加摄像头（RTSP 地址或视频文件路径）→ 画安全区 → 加规则（enter/enter_no_ppe/exit/occupancy_over）→ 启动 → 看事件与实时画面。

只用后端 API 时：`cd server && D:\LabSentinel\m0-venv\Scripts\python.exe -m uvicorn app.main:app --port 8000`

### 1.6 生产化（可选）

- Web：`cd web && npm run build`，把 `dist/` 交给 nginx/IIS，`/api` 反代到 8000
- 开机自启：任务计划程序或 NSSM 注册三个进程；go2rtc 必须带 `--config tools\go2rtc.yaml`
- 防火墙放行 8000/TCP、1984/TCP+UDP（WebRTC 的 ICE 需要 UDP；`tools/go2rtc.yaml` 已把 ICE 固定在 1984）
- 浏览器与 go2rtc 需网络互通；跨网段/公网访问请走 `wss://` 反向代理

### 1.7 常见问题（Windows）

| 现象 | 原因/处理 |
|---|---|
| 视频有画面但浏览器播不了事件视频 | 缺 OpenH264 编码库：把 `openh264-2.5.0-win64.dll` 放到 `m0-venv\Lib\site-packages\cv2\`（server/app/__init__.py 已自动加 PATH）；仍失败会回退 mp4v（ffplay 可播） |
| 实时画面一直"重连中" | go2rtc 未启动 / 1984 被防火墙拦 / 用 IP 而非 localhost 时 mDNS 候选失败 |
| 2 路以上分析后摄像头"静默停止" | 旧版本 DirectML 并发 bug，已在 engine.py 全局串行锁修复（2026-10-26）；确认服务端已重启到新代码 |
| pip 安装超时 | 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`；npm 加 `--registry=https://registry.npmmirror.com` |

## 2. Docker / Linux 部署

```bash
mkdir -p models data
cp <yolo11n.onnx> models/            # 模型不进镜像
docker compose up -d                 # web: http://<host>:8080，API: 8000
```

- 数据持久化：`./data`（事件库 SQLite、截图 `data/snapshots/`、视频 `data/videos/`）
- 查看日志：`docker compose logs -f labsentinel`
- 容器内默认 `LS_BACKEND_ORDER=cpu`；确认宿主机核显直通后再改 directml
- 更新：`docker compose build && docker compose up -d`

**人脸模块（可选，默认关闭）**：

```bash
# 1. 仅首次/开启人脸时启动 CompreFace 栈（宿主 18000）
docker compose --profile face up -d
# 2. 在 CompreFace 界面创建应用，拿 API Key
# 3. .env 配 LS_FACE_ENABLED=true + LS_COMPREFACE_API_KEY，重启 labsentinel
```

> 附带的 CompreFace 服务段为按官方 compose 精简的 best-effort 版本；若启动异常，
> 请以 CompreFace 官方 docker-compose.yml 替换，只需保证 `compreface-api:8000` 在 compose 网络内可达。

## 3. 摄像头接入

| 品牌/来源 | RTSP 地址模板 | 说明 |
|---|---|---|
| 海康威视 | `rtsp://用户名:密码@IP:554/Streaming/Channels/101`（主码流）/ `102`（子码流） | 分析建议用子码流（720p） |
| 大华 | `rtsp://用户名:密码@IP:554/cam/realmonitor?channel=1&subtype=0`（主）/ `subtype=1`（子） | |
| 宇视 | `rtsp://用户名:密码@IP:554/media/video1` | |
| 手机模拟 | 手机装"IP 摄像头"类 App，取局域网 RTSP 地址 | 联调用；务必用 5GHz 局域网 |
| 视频文件 | 直接填文件路径，类型选"视频文件" | 演示用；`LS_FILE_LOOP=true` 可循环 |

注意事项：
- 摄像头编码建议 **H.264**（浏览器 WebRTC 直通）；HEVC 需 go2rtc 转码（`ffmpeg:` 源加 `#video=h264`）
- 分析帧率默认 5 FPS/路，`LS_ANALYSIS_FPS` 可降；多路并发能力见 [51-loadtest-report.md](./51-loadtest-report.md)
- 摄像头账号建议用只读/子码流专用账号

### 3.1 USB 摄像头 / OBS 虚拟摄像头（联调）

没有真实 IP 摄像头时，可用本机 USB 摄像头或 OBS 虚拟摄像头验证设备链路：

```bat
:: 1. 枚举可打开的索引（并保存首帧确认画面）
python tools\list_cameras.py --snapshot-dir logs\cam_probe

:: 2. 用 OBS Virtual Camera 播放演示视频（需已安装 OBS 虚拟摄像头驱动 + pyvirtualcam）
python tools\virtual_cam_feed.py --video m0-spike\data\lab-walk-24076.mp4
```

然后在「摄像头」页添加：类型 **USB**、设备号填 `0`（物理摄像头）或 `1`（OBS 虚拟摄像头，以枚举结果为准）。
服务端会把 `"0"`/`"1"` 转成 OpenCV 设备号；USB 常返回 `fps=-1`，服务端已按 30 兜底。

注意：
- OBS 虚拟摄像头只用于联调，**不能替代真实 RTSP 24h 验收**；
- 物理摄像头黑屏先检查系统隐私开关/物理遮挡；
- `virtual_cam_feed.py` 依赖 `pyvirtualcam`（`pip install pyvirtualcam`），不要与真实摄像头验收同时跑。

## 3.5 管理鉴权（可选，任务16）

服务端默认**不启用鉴权**（内网信任场景）。公网/半公开环境建议启用：

```ini
LS_ADMIN_TOKEN=your-secret-token    # server/.env；为空即不启用
```

- 启用后**所有写操作**（POST/DELETE：加删摄像头/安全区/规则、事件处置、死信重发、维护清理、人脸注册删除）
  需带请求头 `X-Admin-Token: <token>`，否则 401
- `GET /api/system` 永不拦截（健康检查）；读操作默认放行，`LS_AUTH_READ_PROTECTED=true` 可一并保护
- Web 端：在「摄像头」页顶部填写令牌（仅存浏览器 localStorage），401 时会有明确提示
- WebSocket：`ws://host/ws/events?token=<token>`（URL 传参有日志泄漏风险，建议内网用）
- 部署验收：`POST /api/alert-test` 会逐渠道自检（含 401 路径验证）

> 常见问题集中答疑见 [部署FAQ.md](部署FAQ.md)（网络/依赖冲突/端口/DML/训练/标注/告警/前端 八类）。

## 4. 告警渠道配置

| 渠道 | 去哪拿 | 配置项 | 备注 |
|---|---|---|---|
| 应用内 | 无需配置 | — | Web 端右上角 WS 状态，事件实时弹出 |
| 企业微信 | 群 → 添加群机器人 → 复制 Webhook | `LS_WECOM_WEBHOOK` | 仅 `qyapi.weixin.qq.com` |
| 钉钉 | 群设置 → 智能群助手 → 添加机器人 → 自定义 | `LS_DINGTALK_WEBHOOK` | 仅 `oapi.dingtalk.com` |
| 飞书 | 群设置 → 群机器人 → 自定义机器人 | `LS_FEISHU_WEBHOOK` | 仅 `open.feishu.cn` |
| 微信（Server酱） | sct.ftqq.com 微信扫码登录 → SendKey | `LS_SERVERCHAN_SENDKEY` | 推送到微信服务号 |
| 微信（PushPlus） | pushplus.plus 微信登录 → token | `LS_PUSHPLUS_TOKEN` | 公众号消息 |
| QQ（Qmsg酱） | qmsg.zendee.cn 登录 → key | `LS_QMSG_KEY` + `LS_QMSG_QQ` | 需加机器人好友；QQ 侧风控严 |
| 邮箱 | QQ 邮箱：设置 → 账户 → 开启 SMTP → 授权码 | `LS_SMTP_HOST/PORT/USER/PASS` + `LS_ALERT_EMAIL_TO` | 端口 465 走 SSL |

安全设计：所有 webhook 强制 https + 域名白名单 + 不跟随重定向（防 SSRF）；发送异步化，不阻塞分析线程。
短信渠道未内置（需付费网关，按需自行扩展 `_HttpPushChannel` 子类）。

## 5. 人脸比对合规自查清单（开启前逐条确认）

依据《人脸识别技术应用安全管理办法》（2026-06-01 施行），详见
[20-research/00-synthesis.md §7](./20-research/00-synthesis.md)：

- [ ] 已就人脸信息的收集、使用**单独取得**被识别人员同意（注册接口强制 `consent=true`，记录落 `face_consents` 表）
- [ ] 采集现场设置**显著的人脸识别提示标识**
- [ ] 明确告知处理目的、方式、保存期限，并提供删除渠道
- [ ] 人脸信息不出境、不用于考勤等未告知用途
- [ ] 处理超过 **10 万人**人脸信息已依规备案
- [ ] 定期核查人员库与同意记录，离职/撤回同意者及时删除（`DELETE /api/face/persons/{subject}`）
- [ ] 一键清除演练过：`DELETE /api/face/persons/all`（人员库 + 同意记录）
- [ ] 人脸数据目录（`data/compreface-db`）已纳入备份/销毁流程

## 6. 验收自检（部署完成 5 分钟）

1. `GET /api/system` 返回 backend 与摄像头状态
2. 添加一路摄像头 → 启动 → `GET /api/cameras/{id}/snapshot` 有画面
3. 画安全区 + 加 enter 规则 → 人进入 → 事件出现且 `has_video=true`
4. 事件页 ▶ 能播 H.264 视频；`GET /api/events/{id}/video` 返回 video/mp4
5. 报表页有当日折线与小时分布
6. 配置一个告警渠道后，手动制造事件，渠道收到统一文案
7. 摄像头页"实时画面"能出 WebRTC 画面（延迟约 1 秒）
