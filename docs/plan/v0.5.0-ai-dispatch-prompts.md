# LabSentinel v0.5.0 多 AI 分发任务书与主线审阅清单（`LS-050` ～ `LS-057`）

> **用途**：本文件面向多 AI 协作模式——将 `v0.5.0` 的 8 个独立批次拆分为**可直接复制发送给其他 AI 执行的任务卡片**，并在文末附带**主线审阅官验收清单**。
> **协作流**：分发卡片给执行 AI → 执行 AI 在本地实现并跑完门禁 → 提交或产出改动后交给主线 AI 按清单逐项审阅、修正并合入 `main`。

## 9. 主线审阅官（Reviewer）验收清单

当其他 AI 完成任意批次交回成果时，主线 AI 按以下 7 条逐项审阅并直接修补缺陷：

1. **架构与红线核查**：是否触碰 Python 产品代码？是否引入 `chrono` 或手写 UTC？是否新增 `unsafe`？`DirectML` 推理是否 100% 走 `dml_lock()`？Windows 子进程是否全带 `CREATE_NO_WINDOW`？
2. **契约与路由核查**：新增 API 是否全部登记在 `ROUTE_INVENTORY` 且通过 `scripts/contract_audit.py`？前端解包是否对数组/空对象做防御？
3. **安全与脱敏核查**：新增管理接口是否纳入 `ADMIN_GETS` / 写鉴权？诊断包/日志/错误响应是否泄漏 API Key、Webhook Secret 或 RTSP 密码？文件读写是否有 `Path::starts_with` containment 校验？
4. **并发与资源核查**：新增后台线程/子进程（如 `go2rtc`、重试消费者、定时日报）是否接入 `graceful_shutdown` 与 Windows Job Object？是否有无界内存增长或忙等循环？
5. **UI 与主题核查**：浅色/深色主题是否均使用设计令牌、对比度达标？新组件是否遵循单根结构且在移动端/小窗不溢出？
6. **测试与门禁复跑**：主线 AI 必须亲自复跑 Rust 三连 + Web 测试/构建 + `contract_audit.py`，不轻信执行方口头“已通过”。
7. **接力文件与提交规范**：确认 `Cargo.lock` 同步、更新 `task_registry.md` / `progress.md` / `修改记录_会话备忘.md`，以 `windyxyz <siyuan060203@163.com>` 提交至本地 `main`。
