## 结论与后续

- L1 机制层（抽帧/跟踪/迟滞/规则/文案/时间戳映射）与 Python **逐位一致**已证明；
- 94.4% 距 98% 门槛差 1 个临界样本，消除路径有二（T-325 后续）：
  1. Rust 侧 resize 换 OpenCV 等价插值（image crate 的 CatmullRom 与 cv2.INTER_LINEAR
     存在已知的 ±0.005 conf 级差异），或
  2. 阈值边界滞回（conf ∈ [th-0.01, th] 的框保留给跟踪、不触发检测事件）——同时利于
     Python 侧的抖动抑制；

诊断（tools/detect_compare.py 思路 + --dump-dets）：
- 检测总量 Python 380 框 vs Rust 384 框，仅 **8/322 帧（2.5%）数量差 ±1**（双侧互有，
  NMS/阈值边界的浮点临界对）；NMS 已对齐（同分稳定序 + 分母 +1e-9）后差异不变；
- 检测层小差在**多人遮挡场景被 ByteTrack 关联放大**：Kalman 预测的浮点累积差 →
  遮挡帧的匹配选择不同 → 轨迹合并/分裂路径分叉 → ID 重映射失效（T-324 的
  "轨迹划分一致"前提是输入检测序列完全一致）。

**定位**：检测框 IoU ≥ 0.99（§13.8 L1 检测标准）已达标；事件级一致率的剩余差距
归属**推理后端浮点差**（tract vs ORT/DML），非管线逻辑缺陷——切到同一后端
（T-328 计划的 ls-infer feature=ort，随包 onnxruntime）即自然收敛。tract 后端的
定位是"无 ORT 环境的兜底实现"（本机 windows-gnu 无 libclang 的替代路径），
L1 灰度验收应以 ort 后端跑黄金语料为准（验收口径记录，不阻塞机制层对齐结论）。
