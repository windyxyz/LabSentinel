# 70 · 开源发布规划

> v0.1（2026-10-26）· 目标：把 LabSentinel 发布为**可信、可部署、有人愿意用**的开源项目。

## 版本策略

| 版本 | 内容 | 发布条件 |
|---|---|---|
| **v0.1.0-alpha（内测）** | 当前 M1 能力：单路分析、实验服告警、事件/报表/存证 | v2 模型上线 + 真实摄像头 24h 稳定 |

| **v1.0.0** | 文档/CI/示例数据/贡献指南齐备，发布公告 | M4 |

语义化版本；实验性功能（NPU 包、鸿蒙端、GB28181）不阻塞主版本。

## 发布渠道与社区运营

1. **GitHub Release**：源码包 + `docker-compose` 一键部署；模型单独 Release Assets（或安装脚本下载 + 校验 sha256）
2. **发布公告**：中文技术社区（V2EX、少数派、B 站演示视频、知乎）——演示视频是最强弹药：**真实实验室画面（脱敏/公开素材）+ 白大褂漏穿告警实录**
3. **Issue 模板**：bug / feature request / 模型误报（附截图，脱敏要求写明）
4. **贡献指南**：开发环境（镜像源、venv、测试）、任务包体系、ADR 流程（重大决策先写 ADR）
5. **模型迭代透明化**：每次模型版本发布附评估表（AP/误报率/数据来源），数据集版本用 CC BY 4.0 合并版（需逐个数据集核对再分发许可）

## 发布节奏（建议）

- **T+0**（本周）：v2 模型 + 稳定性修复 → 私有 alpha（用户实验室）
- **T+2 周**：M2A 实时画面 + 部署文档 → **公开发布 v0.1.0-alpha**（先 GitHub，观察 issues）
- **T+4~6 周**：多路压测数据 + 安卓端 → v0.2.0 + 社区公告
- **T+8 周**：人脸模块（默认关）+ 推送 → v0.3.0
- **T+12 周**：v1.0.0（CI/文档/示例/贡献者文档齐）

## 停止线（什么情况下不发布）

- v2 模型在真实画面仍不可用（Lab Coat 检出率 <60% 或误报率 >20%/天）→ 先把数据飞轮跑一轮，不发布"工业垃圾"
- 串行锁修复未经 24h 真实摄像头验证 → 不发布（死机事故重演会杀死项目信誉）
