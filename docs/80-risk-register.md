## 一、已发生事故复盘

### 🔴 A1 · DirectML 并发推理导致整机死机（2026-10-26，两次）

**现象**：短时间内 Windows 三次 Kernel-Power 41 异常重启记录（08:34/08:45/08:53），无蓝屏（BugCheck 1001）、无 WHEA 硬件错误、无资源耗尽（Event 2004）。用户感知为"卡死→强制重启"。

**根因（子代理定位，主线复核证据链）**：ONNX Runtime DirectML Execution Provider 的会话**跨线程并发 `Run` 不是线程安全的**（AMD 驱动级缺陷）。服务端架构中多个 CameraWorker 线程共享同一全局引擎实例，且人检引擎与 PPE 引擎是两个 DML 会话——≥2 路并发推理时 GPU 驱动挂死，进而冻结整个系统（GPU 驱动挂死通常表现为整机冻结而非蓝屏，与事件日志完全吻合）。触发场景：子代理执行多路并发测试 + 主线同时运行模型推理。

**修复（已入代码）**：`engine.py` 模块级全局锁 `_ACCEL_LOCK`，所有 directml/vitisai 后端的 `sess.run` 一律串行（跨实例共享）；CPU 后端不加锁。回归测试 `test_accel_run_serializes` 已验证串行性（FakeSess 注入，不碰真 DML）。

**教训与规则**：
1. **DML/VitisAI 会话永不并发 Run**——新代码只能通过 `Engine._run()` 调用推理，禁止直接 `sess.run`（代码审查项）。
2. **并发压测（任务 07 类）必须在锁修复的版本上进行**，且一次只跑一个压测进程。
3. **训练/压测禁止与子代理任务并发**（本次另一诱因：CPU 争用加剧了系统不稳定）。
4. 系统级监控建议：部署时记录 Kernel-Power 41 作为稳定性红线指标。

**现状**：修复已提交，待子代理跑全量测试 + 真实摄像头 24h 稳定性验证。
